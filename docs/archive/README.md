## 继任调研文档的命名与格式规范

**命名**（后续调研一律遵守）：

```
research-YYYY-MM-DD.html                 # 全景轮（生态位复查，一文件一日期）
research-YYYY-MM-DD-<topic-slug>.html    # 单主题补充轮（如 research-2026-12-01-moonbit-1-0.html）
```

- 前缀固定 `research-`；日期为调研完成日（ISO 格式）；单主题轮加短横线
  连接的小写英文主题 slug。
- 日期后缀天然按文件名排序呈现轮次时序；**不覆盖旧轮文件**（每轮新文件，
  旧轮是时点快照）。

**格式**（对齐 docs/reviews/ 报告的自包含风格）：

- UTF-8 单文件 HTML，**零外部资源**（无外链字体/脚本/图片——离线可读，
  归档不腐）。
- 头部 meta 块注明：调研轮次、日期、方式、与上轮的关键差异。
- 结构：§0 结论摘要（先读）→ 竞品/主题逐项 → 生态趋势 → 对照表 →
  "对 Lom 的行动启示（记录，非裁决）" → 方法与局限 → 来源总目。
- **严禁虚构**：所有数字/日期/事实必须来自来源链接，检索时点写明；
  未确认的事实在正文标注"下轮复核"。**关键数字必须打开来源原文核对，
  不得转述搜索摘要**（第 1 轮的教训：MoonBit 版本号/日期两处转述失实，
  被第七轮审查 R43 抓出——摘要说 v0.9 而原文已到 v0.10.9）。
- 行动启示只记录事实输入，方向与发布裁决权在用户（发布线冻结裁决不受
  调研影响）。
