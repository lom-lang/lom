Lom 生态位调研（第一轮继任轮）

调研轮次：启动期四份调研（2026-07/29–08/02）后的第一轮继任调研
调研日期：2026-09-15（Lom v1.2.0，语言面冻结 + 双后端 + 三层自举 + 差分 10000 收官后）
调研方式：公开网络检索（MoonBit 官网/博客、The Register/InfoQ/Phoronix 等媒体报道、GitHub 项目、SWE-bench 榜单）；所有数字与事实来自文内来源链接，检索时点 2026-09-15
与上轮的关键差异：上轮调研时（立项前）"LLM-repair-native 语言"赛道接近无人区；本轮发现该赛道在 2026 春夏已成热点——出现定位高度重合的大厂背书竞品（Vercel Labs Zero）

0. 结论摘要（先读）

  1. 赛道变热，直接竞品出现：Vercel Labs 于 2026-05 发布、2026-08 正式 ship 的 Zero 语言，其定位——"AI agent 可读、可诊断、可修复"——与 Lom 的核心卖点（lom-diag/v1 稳定诊断码 + lom-fix/v1 修复动作 + 显式效应系统）高度重合，且有 Vercel 的渠道与曝光优势。
  2. 两个历史判断需要修订（HANDOVER §7 / DESIGN_RATIONALE 引用的立项期认知）：Mojo 已于 2026-08-12 发布 1.0 并开源（Qualcomm 收购后），不再"绑定硬件不进编码赛道"；MoonBit 1.0 从 2026 上半年推迟至 Q3（当前 v0.9，2026-04-07），且其 AI-native 叙事持续强化。
  3. 生态趋势与 Lom 同向：spec-driven development 成为主流范式（30+ agentic 框架）；SWE-bench Verified 破 80% 但 SWE-bench Pro（ICML 2026）/SWE-EVO 显示长程修复仍是缺口——"把 agent 的猜测变成协议驱动的修复"恰是 Lom 的赛道论据。
  4. Lom 的差异化资产（当前仍独有）：修复闭环的工程深度（迭代 --apply + fix-history + fix_corpus 回归网）、三层自举自证、双后端 10000 程序差分证据、119 任务评测集与 pass@k 实测、六轮独立审查与冻结治理。Zero/Vera 均处于生态早期，无同等公开证据链。
  5. 风险（如实呈现，非建议）：在"优化到完美前不发布"的冻结裁决下，赛道声量被先发竞品占据的窗口成本在上升；本调研仅记录事实，发布时机决策权在用户。

1. 竞品逐项

1.1 Vercel Labs Zero 最高威胁 · 定位重合

  • 实验性系统编程语言，明确以"AI agent 能读、诊断、修复、交付原生程序"为设计目标：编译 sub-10KiB 原生二进制；zero check --json 返回结构化诊断（稳定错误码 + 精确行列 + 类型化修复元数据）；显式效应；媒体描述为"graph-first language"（[MarkTechPost 2026-05](https://www.marktechpost.com/2026/05/17/vercel-labs-introduces-zero-a-systems-programming-language-designed-so-ai-agents-can-read-repair-and-ship-native-programs/)、[InfoQ 2026-08](https://www.infoq.com/news/2026/08/vercel-ships-zero-ai/)、[Techstrong.ai](https://techstrong.ai/features/vercel-labs-builds-a-programming-language-designed-for-ai-agents/)、[HackerNoon](https://hackernoon.com/vercels-zero-wants-compilers-to-talk-to-ai-agents)、[zerolang.ai](https://zerolang.ai/)）。
  • 与 Lom 的重合面：机器可读诊断协议 + 稳定错误码 + 修复元数据 + 显式效应——四项皆中。
  • Lom 仍独有/领先的点：修复动作的迭代执行闭环（多轮收敛 + 历史留档 + 8 对 fix_corpus 回归网，Zero 公开材料只见到诊断输出未见等价物）；渐进式类型（warning 不拦截的哲学）；自举三层自证与双后端差分（10000 程序）的语义对齐证据；LLM 实测数据（119 任务集 pass@k 99.1%）。Zero 是 Vercel Labs 实验项目，语言成熟度与证据深度待观察。

1.2 MoonBit 最直接对标 · 叙事逼近

  • 1.0 时间线变化：原计划 2026 上半年（[1.0 Roadmap](https://www.moonbitlang.com/blog/roadmap)）→ 官方 updates（2026-08-19）改口 Q3 2026；当前版本 v0.9（2026-04-07），pre-1.0 版本间视为兼容（[官方 updates](https://www.moonbitlang.com/updates/)）。
  • AI-native 叙事强化：2026-09 黑客松与"Software Synthesis Challenge"（以 AI-native 方式构建生产级系统）；路线图明言"AI-native toolchain improvements"。
  • 设计哲学对照（其 2024-04 博客 [AI-native applications](https://www.moonbitlang.com/blog/ai-coding)，本轮重读）：AI 友好三特征 = 易测试 / 快速静态分析 / 安全性；纠错机制 = 编辑器内实时重采样 + 静态分析过滤（token 级实时语义分析，实验称编译率显著提升、性能损耗 ~3%、建议增强延迟 ~0.86s）。
  • 与 Lom 的分界线：MoonBit 的 AI 纠错发生在生成时（采样侧过滤），Lom 发生在生成后（诊断→修复动作→迭代 apply 的闭环）——两者互补而非同构；但对外叙事上"AI-native 语言"这个词的独占性在消失。

1.3 Mojo 判断修订 · 不再排除

  • 1.0 已发：2026-08-12 达成 1.0 里程碑，定位"稳定、生产就绪的通用语言"（[The Register](https://www.theregister.com/ai-and-ml/2026/08/12/modulars-mojo-programming-language-hits-10-milestone/5286545/)）。
  • 已开源：Qualcomm 收购 Modular 后按承诺开源了 Mojo 编译器（[Phoronix 讨论](https://www.phoronix.com/forums/forum/phoronix/latest-phoronix-articles/1652721-modulars-mojo-language-now-open-source-following-qualcomm-acquisition)、[HN](https://news.ycombinator.com/item?id=49358327)）。
  • 生态动向：社区视角——用 Mojo 给 Qualcomm 芯片编 NPU 程序可能让 PC AI 编程"爱好化"；Wikipedia 口径：部分早期目标（完整 Python 兼容等）截至 2026-03 被放弃或推迟。
  • 对立项期判断的修订：HANDOVER §7"Mojo 已被高通收购绑定硬件，不会来 LLM 编码赛道"——开源 + 通用语言定位使其间接进入更大竞场，但其重心（AI 工作负载性能）仍与 Lom（修复闭环）不同轴。

1.4 其他同赛道新面孔

  • Vera（2026-04 前后 HN 热度）："为机器写、不为人写"的静态类型纯函数语言，无歧义语法、确定性解析，编译到 WASM（[veralang.dev](https://veralang.dev/)、[GitHub](https://github.com/aallan/vera)）。比 Lom 更极端（放弃人类可读优先），人群不同。
  • BirdDisk：独立小项目，自称"LLM-first 语言 + 编译器栈：人类可读 + 确定性解析 + 机器可行动诊断"（[GitHub](https://github.com/Jawbreaker1/bird_disk_code)）——表述与 Lom 设计支柱几乎逐字重合，但工程规模小。
  • Plang/PromptLanguage（[ESWA 2025 论文](https://www.sciencedirect.com/science/article/pii/S0957417425037339)）：string-first、面向 LLM 提示工程的语言——不同赛道（提示编排 vs 程序修复）。

2. 生态与能力趋势

  • Spec-driven development 主流化：六大 SDD 工具同台（Augment Cosmos / Kiro / GitHub Spec Kit / OpenSpec / BMAD-METHOD / Cursor，[Augment 盘点](https://www.augmentcode.com/tools/best-spec-driven-development-tools)）；30+ agentic 编码框架图谱（[Medium 深度图](https://medium.com/@visrow/spec-driven-development-is-eating-software-engineering-a-map-of-30-agentic-coding-frameworks-6ac0b5e2b484)）；IBM 提"spec-as-source"终局（[IBM](https://www.ibm.com/think/topics/spec-driven-development)）。→ 与 Lom 同向：Lom 的 SPEC_FOR_AI.md（喂 LLM 的精简规范）+ 诊断协议本质上是"语言级 spec 协议化"。
  • Agent 修复能力：单点强、长程弱：SWE-bench Verified 2026 年破 80%（[Multiware](https://multiwaresolutions.com/blog/ai-coding-agents-swe-bench-2026)、[官方榜](https://www.swebench.com/)）；但 SWE-bench Pro（ICML 2026）揭示长程多议题真实场景仍有大缺口，新基准 SWE-EVO 专测代码库持续演化（[ICML 页面](https://icml.cc/virtual/2026/poster/61047)）。→ 修复可靠性（而非单次成功率）是下一战场——协议驱动的修复闭环（Lom 路线）正是针对该缺口的方案论据。
  • 2026 语言共识图景：两条流派——(a) 性能型 AI 语言（Mojo/MoonBit/Bend）；(b) LLM-first 设计原则（无歧义语法、强工具、可验证语义、机器可读错误）（[Syracuse 榜单](https://ischool.syracuse.edu/top-ai-programming-languages/)、[Artezio 2026 playbook](https://www.artezio.com/pressroom/blog/playbook-development-languages/) 等）。Lom 属 (b) 中"修复优先"细分。

4. 对 Lom 的行动启示（记录，非裁决）

  • 差异化叙事需要更新措辞：从"AI-native 语言（稀缺定位）"收敛为"修复闭环 + 证据链最深的 agent-native 语言"——竞品已有诊断 JSON，但公开材料中尚无与 fix 引擎（计划→置信度分级→迭代应用→历史留档→语料回归）等深的闭环。
  • 历史判断修订两处（HANDOVER §7 / DESIGN_RATIONALE 若引用需注新）：Mojo 开源 1.0；MoonBit 1.0 推迟 Q3 且 AI 叙事强化。
  • 零依赖供应链 + 冻结治理在 agent 生成代码安全语境下（MoonBit 博客亦把"AI 生成代码安全"列为核心挑战）是可对外强调的资产。
  • 发布窗口：Zero 的渠道优势意味着时间成本真实存在；发布时机仍是用户冻结裁决，本调研不改变它，仅提供事实输入。
  • 可考虑的低成本跟进（均不破冻结）：README 差异化段落与 Zero/Vera 对照的公开对照表；把 pass@k/差分证据链整理为一页对外材料。
