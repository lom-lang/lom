0. 结论摘要

  1. 第 1 轮判断修正一："Zero 公开材料未见修复闭环等价物"——不准确。Zero 官方 diagnostics 页明确有 zero fix --plan --json（"returns a repair plan, not an automatic edit"）+ zero patch 补丁循环，计划层与 Lom 的 lom fix --plan 同名同语义。Lom 仍独有的是执行层：--apply 迭代自动应用（多轮收敛三刹车）+ 置信度分级（High 才自动改）+ fix-history 留档 + 8 对 fix_corpus 回归网——Zero 明确把应用交给 agent，且要求"先解释补丁、后验证用户可见行为"。
  2. 第 1 轮判断修正二：证据链竞争者 +1——Vera 也做了 LLM 实测（"six of the nine write 100% correct Vera, a language none of them was trained on"）。但形态弱于 Lom（无 pass@k 无偏估计、无修复类任务集、无独立审查），且成熟度 v0.1.13。
  3. 三范式定位清晰化（本轮最大产出）：Zero=图优先（语义图是程序数据库，文本只是投影，agent 不应直接编辑投影——最激进 agent-first）；Vera=模型专属（De Bruijn 槽位代替变量名、强制契约 + Z3 验证，"The model doesn't need to be right, it needs to be checkable"——牺牲人类可读性换可验证性）；Lom=文本优先人机共读 + 修复执行闭环（源码是单一事实源，人保留直接编辑主权）。三者同题不同解，Lom 的中间道路定位成立且未被占。
  4. 惊人的一致性：Zero 的错误码体系（三字母前缀+三位数字：NAM003/BLD002/RGP003/GRF013/CIMP003）与 Lom（LEX/PARSE/TYPE/NAM/EFF/MAT/RUNTIME + 三位数）同款命名法，且 Zero 的 NAM003 同为"未知标识符"——收敛进化到同一形态是赛道方向正确的旁证。Vera 用 E001-E702+W001/W002 连续编号（无类别前缀）。
  5. Ⓒ 一页纸的核心论点更新：从"修复闭环最深"细化为——"诊断计划层三家都有；修复执行自动化（apply/置信度/历史/语料回归）仍只此一家；且只有 Lom 保有文本源码主权与全套证据链（自举/差分 10000/pass@k/七轮审查）"。

1. Zero 深读（一手：zerolang.ai 主页 / learn / diagnostics 页）

1.1 范式：图优先（与 Lom 的根本差异）

  • 官方定位："an experimental graph-native programming language where the semantic graph is the program database"（[GitHub](https://github.com/vercel-labs/zerolang)）——程序本体是语义图数据库，文本（.0 投影文件）只是 source map 式的可读投影："That does not mean the agent should edit that file."，人工编辑被限定为 "rare manual edits"。
  • 编辑单位是图补丁：zero patch --expect-graph-hash graph:... --op 'set node="#expr_..." field="value" expect="..." value="..."'——由 graph hash 与期望值双重守卫，"Stale or invalid edits fail before they touch the store"。
  • 工具链：init/patch/run/query/status/explain，双轨（图数据库 + 投影），编译产物 sub-10KiB 原生二进制；主页标注 Experimental、5.4k stars、"Expect breaking changes... not against production systems"。

1.2 诊断与修复（对标核心）

  • 错误码：三字母前缀+三位数——NAM003（未知标识符）/BLD002/RGP003/GRF013/CIMP003/005；任意码可 zero explain CODE 查询。
  • 文本诊断字段（NAM003 示例原文逐行）：位置 file:line:col、上下文行+^^^ span、rule:（违反的规则）、expected: / actual:（结构化分离于消息文本——Lom 把这两者揉在 message 里，可吸收的设计点）、fix:（建议 + edit shape 标签如 (local-edit)）、explain:（深挖入口）。
  • JSON 模式："JSON is for automation, edit planning, CI, editors, and exact diagnostic fields"——官方页未公布逐字段 schema 与完整示例（字段类别：spans/codes/fix ids/readiness facts）。
  • 修复闭环形态：zero fix --plan --json 返回修复计划（非自动编辑）→ agent 生成补丁文件 → zero patch 应用 → 重跑聚焦检查。官方要求 agent "explain the patch it will apply and validate the user-visible behavior afterward"；图优先包的修复"should normally be a graph patch"。
  • 与 Lom 逐项对照：诊断计划层（fix --plan）同构同义；执行层缺席——无 --apply 等价物、无置信度分级自动应用策略、无修复历史留档、无修复语料回归网（这些是 Lom M1-M4 + fix_corpus 的独有资产）。edit shape 标签 ≈ lom-fix/v1 的 action 类型（replace/insert），粒度更粗。

2. Vera 深读（一手：GitHub README）

  • 定位："designed for large language models to write"——核心哲学 "The model doesn't need to be right, it needs to be checkable"；三大手段 "Names are replaced by structural references. Contracts are mandatory. Effects are typed."。
  • 诊断："Vera produces instructions for the model that wrote the code"——每条错误含 what/why/how to fix with a concrete code example/spec reference 四要素；稳定码 E001-E702 + W001/W002，--json 结构化输出，vera errors --json 列全部注册项。
  • 激进设计：无变量名（类型化 De Bruijn 槽位 @Int.0/@Int.1）；强制契约（requires/ensures/effects 三段 + 递归 decreases）；SQL 注入在类型检查层被禁止（查询文本必须字面写在源码）；LALR(1) 确定性语法 + vera fmt 规范化为唯一形式。
  • 验证栈：check（解析+类型）/ verify（Z3 契约验证）/ run（WASM）；浏览器与 WASI p2 目标；LSP 带 typed-hole 补全。
  • 成熟度与证据："active development at v0.1.13"，2000+ commits、12290 测试、95% 覆盖、244 一致性程序；LLM 实测："six of the nine write 100% correct Vera"（9 模型、零训练语言——形态类似 Lom 的多模型实测，但无 pass@k、无修复任务类目、无独立审查）。
  • 修复：错误内嵌 "Fix:" 段落（含代码示例），无 plan/apply 引擎——修复建议是文档性的，不产出结构化修复动作。

4. 对 Lom 的行动启示（记录，非裁决）

  • Ⓒ 一页纸论点定稿依据（本节即供料）："诊断计划层已是行业标配（Zero/Lom 同构、Vera 文档化）；修复执行自动化（迭代 apply + 置信度 + 历史 + 语料回归）仍是 Lom 独有；文本源码主权是 Lom 与图优先/模型专属两范式的分界——人永远可以直接改源码，修复闭环围绕源码而非图投影构建。"
  • 可吸收的设计点（冻结期外记录，均不动语言面）：①诊断的 expected/actual 独立字段（lom-diag/v2 的 additive 演进方向——冻结 §14 允许 schema additive？需核实"零新诊断码"边界，列为待裁决项而非建议）；②"explain 错误码"的等价物（Lom 的诊断文档化已由 SPEC_FOR_AI 码表承担，命令化收益存疑）；③Vera 的 spec reference 字段（诊断指向规范章节——Lom hint 已含等价信息文本）。
  • 错误码命名收敛（Zero 与 Lom 同款三字母+三位）可作为"设计收敛"的对外叙事素材。
  • Vera 的 Z3 契约验证是 Lom 没有的维度（形式化验证）——一页纸如实标注为 Vera 领先项，避免失实宣称（Lom 的验证形态是 golden/差分/自举/审查的工程证据链）。
