6. 开账（只开不修；从 R117 起）

R117（P3，文档精度/登记面缺口）——wasm 侧源码嵌套深度（parser 递归面）无量化登记，且 trap 归因文案与实测错误形态不完全对应
可复现形态：node target/probes/r27/probe_depth.mjs（同款 harness）——嵌套括号表达式 400 层正常 / 500 层 RuntimeError: memory access out of bounds；桌面同源码 3,000 层 rc=0 输出 1（256MB 栈）。即：同一合法 .lom 源码，桌面通过而浏览器 trap。该 trap 不静默（worker.js 转译 {trap:true} → app.js"⚠ 栈上限（浏览器引擎限制）"文案 + 5s 看门狗 + terminate 重建——三层兜底在位），且 worker.js 注释（"病态嵌套源码打爆 JS 引擎栈"）与 README 登记边界（"browser recursion ≪ desktop"）已有定性覆盖；缺口有三：① README registered boundaries 句与 designs/0019 登记的"recursion"仅指 Lom 程序解释器调用深度（守卫 300 结构化先报），未明确源码嵌套深度（parser/编译侧递归）同受引擎栈物理约束且无结构化守卫（node 实测阈值 ≈500，与解释器帧极限同量级但属另一路径）；② 无量化数字入档（400/500 分界）；③ app.js L128 与 worker.js L5 把 trap 一律归因"栈上限/call stack exhausted"，node 实测错误为 "memory access out of bounds"、P5a 形态为 "unreachable"——成因文案不精确。
候选处置（供裁决）：a) README registered boundaries 句补一句"source-code nesting depth shares the same engine-stack ceiling (~500 nested expressions trap in node; desktop's 256MB stack handles 3000+)， surfaced as a translated trap, not a structured diagnostic"；b) app.js trap 文案改中性（"wasm 引擎执行限制"）。
应修 = 文档登记句补全 + UI 文案中性化（纯文档/文案，零行为变化）。绝不能这样修 = ①给 parser 加深度守卫输出新诊断（新增诊断码/诊断面变化触语言面 v1.0 冻结，须新 RFC，且改变 wasm/桌面双侧行为面）；②harness/worker 吞掉 RuntimeError 谎报 exitCode=0（掩盖真实终态，违反"永不拦截"与诚实诊断设计）。

R118（P4，harness API 契约边缘）——run({args: []}) 空数组绕过默认 argv
可复现形态：await rt.run({ source: …, args: [] })——harness.js run() 以 args || ["lom", "/playground.lom"] 取默认，空数组为 truthy 直透 wasm → 宿主 argv[1] 越界 → RuntimeError: unreachable trap（非 proc_exit，exitCode 语义丢失，UI 误标"栈上限"）。可达性：页面（app.js 恒传两元素 args）与冒烟均不可达，仅 API 直接调用方误用面。
候选处置：默认值判断改 (args && args.length) ? args : […默认]，或 harness 头部注释注明"args 必须至少含虚拟脚本路径"。应修 = 一行防御或一句契约注释。绝不能这样修 = 在 wasm/宿主侧为空 argv 加新 CLI 诊断（改诊断面，触冻结且为不可达面过度设计）。

备注三条（不开账）：①"桌面路径逐字节不变"措辞语境 = 桌面编译路径行为不变（全量回归+quine/hex 实证），src 文本有 cfg 门内缩进移动——commit 语境清晰非失真；②topics 现状 14 个无 wasd（TODO 时点记录 15+wasd 待移除，用户已修正——时点快照无矛盾）；③golden expected.txt 入库 CRLF vs 进程 LF（Windows 已知形态，LF 归一逐字一致，verify_selfhost run 模式已覆盖对拍）。
