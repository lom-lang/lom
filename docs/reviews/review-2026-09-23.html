本轮评级：B（仅评本轮时点及本轮检验面，不外推到整改后或整个 Lom 语言）。新开建议 2×P1、2×P2，无 P0。L2.3-a/b/c1 的官方 72/72 与全仓门禁均通过，但独立反例中有两类合法输入被 L2 静默错编译（块作用域、闭包同名符号捕获），一类合法 Bool 比较输出不可实例化 WASM，另有一类合法分支局部绑定被错误拒绝。宿主 WASM 对这些正例的行为已逐一作为对照实跑。

1. 方法、范围与可复现入口

先独立阅读交接指定章节、十三审报告、LANGUAGE_SPEC §14、RFC-0004 修订 1–9、闭包设计与 RFC-0003（尤其页尾 OOB 修订 25–29），再读宿主 src/wasm_codegen.rs 与 L2 examples/selfhost/self_comp.lom 的相关分支。正例均穿过真实 lom build / lom self_comp.lom -- CLI、hex 解码、WASM、Node；负例直接检查 COMPILE-ERROR、原因和 hex 不存在。单独的 --check 或 WASM verifier 均不作为行为正确性证明。

下述自构探针的源码完整附在 §4，复制到 target/probes/<名>.lom 后，在仓库根目录的 PowerShell 执行：

$case = 'r14_if_scope'   # 换成 §4 中任一探针名
./target/release/lom.exe build "target/probes/$case.lom" --target wasm -o "target/probes/$case.host.wasm"
./target/release/lom.exe examples/selfhost/self_comp.lom -- "target/probes/$case.lom" "target/probes/$case.hex"
python tools/hex2wasm.py "target/probes/$case.hex" "target/probes/$case.l2.wasm"
node eval/runner/run_wasm.mjs "target/probes/$case.host.wasm"
node tools/selfcomp/run_selfcomp.mjs "target/probes/$case.l2.wasm"

对被拒绝的探针，前两条即可对照；L2 驱动在 COMPILE-ERROR 时进程本身仍可返回 0，这是现有 CLI 约定，本报告不把该退出码单独定性为缺陷。以下“rc”指 Node 运行产物的退出码，或明确写出的宿主 build 退出码。

F3 · P2
Bool 二元运算产坏 WASM		 RFC-0004 修订 6 的 Bool/比较与修订 9 的“编译期校验不把坏 WASM 留到实例化”边界；即使某 Bool 算术在宿主运行期不合法，L2 也不应声称 COMPILED 后输出不可实例化模块。 r14_bool_eq：宿主 WASM stdout 0、rc0；L2 COMPILED 104 bytes，Node 实例化 rc1，f64.eq expected type f64, found ... i32。r14_bool_arith：宿主 WASM 运行期 trap rc1；L2 COMPILED 90 bytes，Node 实例化 rc1，f64.add expected type f64, found i32.const。 self_comp.lom:2814-2849 的 infer_ex 对比较放行 i32，对算术落到 f64；comp_binary:3230-3274 只专门处理 i64/f64，i32 落到 f64 opcode，未做转型。建议 Bool 的合法相等比较发 i32 操作码；其余未支持运算编译期明确拒绝，正反向均断言无坏 WASM。
F4 · P2
分支局部 let 的合法尾值被拒绝		 RFC-0004 修订 6 声称带 else 的值位 if 可用；修订 8 明言 let y = if ... end、值位嵌套 if 已打通；修订 9 的 Form B 臂尾表达式范围包含此组合。此发现与 F1 的编译期绑定泄漏是不同故障方向。 r14_if_local_tail：宿主 WASM 7\n2、rc0；L2 COMPILE-ERROR: 未定义变量 'x'、无 hex。r14_match_if_local_tail（用户枚举 + Form B + 尾 if）：宿主 7\n0、rc0；L2 COMPILE-ERROR: 未定义变量 'z'、无 hex。 self_comp.lom:2883-2921 中 infer_if_expr 询问 blk_val_ty，后者只看尾表达式、不走本块的 let 声明；match_block_type:3004-3034 只模拟 Form B 顶层 let，深入尾 if 时仍走同一盲区。建议值类型预扫在临时块作用域按声明序建绑定，既不能漏当前块 let，也不能像 F1 那样泄漏到兄弟或外层。

    match t

5. 结论、整改建议及未测面

本轮可确认：c1 枚举构造、递归载荷、嵌套模式、guard、Form A/B、页尾零参对象、无匹配 trap 的已测正例运行对齐；明确的 Result/Option/泛型等拒绝在抽样中真实生效；版本、tag、CI 与文档登记数字未见漂移。但 L2 的编译期严格校验承诺被 F3 的坏 WASM 击穿，行为对拍被 F1/F2 的静默错值击穿，子集覆盖被 F4 的错误拒绝收窄。绿矩阵不能覆盖这些未纳入的词法作用域与类型流组合。

建议开账时把 F1/F2 两类静默错值优先于 F3/F4；每项均加入“应正确运行”及“绝不能静默错编译/产坏 WASM/接受块外未定义名”的反向锁定。F1 与 F4 的块环境改动要联动设计：只修漏入不修漏出，或反之，容易产生新回归。报告仅提出建议，整改次序与实施授权仍归用户。

未测范围：未做 L2 随机程序 500 轮或穷举生成、任意小数正确舍入专项、超过现有 64 KiB 页尾探针的大规模堆增长、深递归/深嵌套极限、L2 编译器自身由其产物自举的 L2.4 闭环；String/List/Map/json/包/return 语句及内建 Result/Option、泛型用户 enum 按现行计划仍属未实现子集，不将其“尚未支持”误报为本轮缺陷。没有安装或运行竞品。未改源代码或既有门禁；临时探针只置于 target/probes/，清理不影响上述内嵌复现文本。
