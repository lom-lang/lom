3. 新发现（R62 起）

ID级别发现与证据建议验收方向（只记录，不开账）
R62 P2 MUT001 High Replace 的同函数嵌套作用域残留错改（R55 整改盲区）。R55 把 let {name} 回扫从全文收窄到"诊断所属函数体内"，但未到绑定作用域粒度：① 函数参数 x 重赋值 + 同函数内闭包 let x 遮蔽时，回扫"体内唯一命中"落在闭包声明上，High Replace 把闭包内绑定错改 let mut——诊断对象（参数）未治疗，final 仍 1 warning，ok:true（applied>0 且 errors==0）宣称修复成功；② 行内注释 let z = 1 # let x = 0——回扫跳过 # 起始行但不感知行中注释边界，注释文本被当声明命中，apply 改注释（无效修复）仍 ok:true。两形态实测复现（上表）。ok 语义本身与 TODO 宣称一致（非失真），但本案暴露"warning 未消除仍报 ok"的误导面。import 混排/空文件/多字节列等其余边界本轮未击穿。 回扫排除嵌套闭包体内与行内注释区间（lexer 层 token 边界可用）；可选：ok 语义对"原诊断未消除"收紧（warning 级修复要求该 code 清零才算 ok）；负向测试锁定两形态（"绝不能这样修"）。
R63 P3 LSP Content-Length 无上限 → 单 header OOM abort。run_lsp 主循环 vec![0u8; len] 直接按声称长度分配：发送 Content-Length: 999999999999 即 memory allocation of 999999999999 bytes failed，进程 abort（rc=0xC0000409）。真实客户端不发此值，但 LSP 是对外协议面，损坏/恶意对端可用 20 字节杀死服务器。随附记录：畸形 JSON 静默丢弃无 -32700 Parse error 响应（LSP 规范建议）；Content-Length: abc/-5 畸形态不崩、流错位后经后续消息可恢复（实测）。5000 层深 JSON 守卫生效不崩（正面）。 Content-Length 上限（如 16MB，超限发 error response 或断连）；畸形 JSON 补 -32700 响应；进程级测试锁定（声称超限不 abort）。
R64 P3 HANDOVER §2.2 命令行控制字符损坏（R60 提交引入）。8178d33（fix(r60)，git blame 实证）在 §2.2 写入 eval_prompt_check 命令时，.\target\release\lom.exe 的字面 \t/\r 被写成真实 TAB(0x09)/LF(0x0A)，命令断成两行（od -c 实证），复制即不可执行。与第四轮 R15 的 0x0C 咬字、CI #92 教训同型复发；§12.1 第 8 条自家纪律"含反斜杠转义的内容只用 Write/Edit 落盘"在该提交中被违反。全仓 md 控制字符扫描（TAB/CR/FF/VT/BS/NUL）为唯一实例；doc_audit 65/65 仍绿——数字锚点 gate 不覆盖命令行完整性。 修复该两行；考虑 doc_audit 或 CI 加"代码块内控制字符扫描"位（md 代码块中 TAB/CR/FF 即红）；整改纪律重申。

其他观察（不计入编号）：① eval_prompt_check / HANDOVER 的 --bin 参数形态（相对 ./target）在 Git Bash 下可用，本轮两种调用均成功；② LSP didOpen 4.4MB 源码 20 秒内完成诊断推送且服务器存活，但 13 万同名函数触发约 21MB 诊断输出——诊断量无上限，正常客户端不会出现，主观推测仅极端场景有感；③ 深类型守卫触发后跳 EOF 会连带吞掉文件后续函数的诊断（设计取舍"防风暴优先"，30000 层阈值内无感）。

5. 审查局限（如实）

  • 本轮没有重放历史 10,000 个差分实例；复验的是 CI 同款冒烟（20 轮）、探针（6/6）与既有报告结构。"差分全量一致"不得引用本轮。
  • LLM raw 留档为 gitignored 本机档案，本轮未复算 pass@k 矩阵，只沿用九审"本机档案支持、fresh clone 无法认证来源"的口径。
  • "独立"是同一维护体系内的 agent 分工，不是外部同行审计；Git 历史单一作者身份，无法归因到个人。
  • LSP 验证基于自构造 stdio 帧（对齐 LSP 规范与 VSCode 常见行为），未接入真实 VSCode 客户端进程。
  • CI 对账基于 GitHub API 的 runs/jobs/annotations 快照（#131-#135），未逐条重放 job 日志。
  • 探针临时文件建于 target/probes/ 并已于报告完成前清理（git status 零残留）；审查阶段未修改任何产品源码、CI 配置与治理文档，未提交未推送。
