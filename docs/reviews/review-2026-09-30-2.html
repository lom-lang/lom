5. 开账（本轮新发现，R104 起）

R104（P1）——两包同名符号冲突：解释器输出同后端跨运行非确定，且与 WASM/L2 确定性选边不一致；全程零诊断

形态：程序依赖的两个包导出同名公开函数（有无 as 别名同款），主文件或包源 import 后调用该符号。

证据（探针 target/probes/r21/adv/p15proj / p15bproj / p15cproj，原文见附录 A）：

# p15b（无别名，libp.shared=11 / libq.shared=22，主文件双 import）——解释器 10 次运行：
11  × 4
22  × 6        # 同一程序、同一后端、不同进程输出不同值，rc 均 0、零诊断
# p15（同款加 as s）：8 次 11×3 / 22×5；p15c（包源 outer.lom 内双依赖撞名，穿批 2b
# load_packages 新代码路径）：8 次 11×4 / 22×4
# 宿主 WASM（同 wasm 5 次）与 L2（3 次）：恒 22（确定性后写覆盖）

根因（主观推测——基于 diff 范围与 process_import 读码，未做旧版宿主行为级对拍）：load_packages 将各包 fn 注册进解释器全局函数表的顺序由依赖图容器的 HashMap 遍历序决定（Rust RandomState 每进程随机），同名 fn 后注册者覆盖先注册者 → 覆盖方向随进程随机；WASM/L2 走合并单元按路径序确定后写赢。SPEC §9.7/§9.8（包章节）未见两包同名符号的语义定义——程序按现行文档不可判非法。

波及面：任何依赖含同名公开符号的两包的程序（主文件 import 与包内 import 均中）；解释器侧跨运行输出漂移本身即破坏确定性承诺（同 wasm 逐字节复现的前提）。差分测试 D5 生成器按 designs/0008 裁决点 2"构造性规避了该形态"，verify_selfcomp pkg_cases 101-105、eval 121、examples 全部无撞名——全库测试零覆盖，属覆盖洞而非测试腐坏。非本批引入：e71749e 对 src/interpreter.rs 的改动仅 load_packages 的 Item::Import 分支新增（别名注册），p15b 主文件形态不经该分支同样复现；函数注册路径未被触碰。

宣称连锁：designs/0013 §1.3"两包别名冲突静默覆盖与 process_import 既有语义一致"——实测不是确定性静默覆盖而是非确定覆盖，该设计句与实际行为不符（批 2 宣称文本本身未直接失真——105 用例不含撞名——但设计依据句失准）。

修法建议（供裁决，非指令）：最小面可在 load_packages 注册包 fn 时按依赖图拓扑序 + 包路径字符串序确定化；更彻底为同名冲突响亮报错（PKG 级诊断，对齐 designs/0008 裁决点 2 甲对 enum/变体撞名的"把静默变显式"路线）。负向锁定：绝不能只把该形态加进 §11f 已知分歧档案了事——解释器同后端跨运行非确定不是"两后端分歧"可容纳的形态（分歧档案的前提是各侧自身确定）；也绝不能用"固定某一次注册顺序"的补丁在不清根源（HashMap 遍历序）的情况下碰运气。

R105（P1）——包符号别名与主文件用户函数同名：解释器静默绕过用户函数走别名，WASM/L2 相反走用户函数；同程序两后端不同值，零诊断

6. 精度备注（不开账，供后续裁决参考）

  1. 包内 stdlib as 别名的三侧形态：宿主双后端放行（p07 300/4/9）、L2 响亮编译拒（io 内建导入暂不支持 as 别名（'println'））。顶层同款（p07b：解释器 5 rc0 / L2 同文案拒）——L2 通用既有边界（顶层/包内一致拒绝，非批 2 引入分叉，也非静默）。修订 42 宣称只覆盖解释器侧打通，无失真；但"105 三侧一致"之外该暗坑形态实为"宿主双侧通/L2 拒"，建议入信任边界清单（HANDOFF_PROMPT 或 SPEC_FOR_AI）供 LLM 生成侧知悉。
  2. Map 注解方言宽度：宿主接受 Map<_Any>（SPEC §9.7 记法形态），L2 注解解析要求双参 Map<String, V>（Map 类型参数数不符（期望 2 得 1），p18 初版）——宿主宽容收/L2 保守拒既有族（二十审 §6 同型），存量用例 87 等均用双参形态。
