3. 证据链（每一条都可机器复验）

  • 修复闭环实测：22 个 error_repair 评测任务（含 warning 级修复题），双模型 × 10 采样 temperature=1.0 下 20/20 全过——repair-native 闭环在高温下依然有效。
  • 双后端语义对齐：树遍历解释器 + 手写零依赖 WASM 后端，10000 个随机生成程序/项目实例 stdout+退出码逐字一致（差分测试四期，含递归 enum、三包依赖链、file/env 深形态）；已知分歧全部文档化（§11f 八条）并有探针守护白名单不腐坏。
  • 自举自证：用 Lom 写的 5703 行解释器（lexer/parser/checker/evaluator/json）三层自证——WASM 载体上的自举解释器解析自身源码，dump 与宿主原生逐字一致。
  • LLM 实测：119 任务评测集，4 模型单采样 + 2 模型 × 10 采样 pass@k：pass@1 = pass@5 = pass@10 = 99.1%（无偏估计）；唯一系统性失败是刻意的 prompt 歧义锚点题。
  • 治理与审查：语言面 v1.0 冻结（变更须 RFC）；七轮独立对抗性审查（R1-R45 整改全关闭）；宣称数字由 CI 机器对账（doc_audit 61 项 + claims.json 分项回加）。
  • 供应链：Rust 实现零第三方依赖、零 unsafe——JSON/JSON-RPC/时间戳全部手写，工具链本身 LLM 可读可修。

4. 判定边界（本页宣称的适用范围——必读）

  • "只此一家"= 在已调研样本中：截至本页时点，深读竞品仅 Zero 与 Vera 两家（docs/archive/ 第 2 轮，一手原文）+ 第 1 轮的浅读扫描——赛道实际有 30+ agentic 框架与工具，未逐一排查。宣称的准确含义是"**在新兴 agent-native 语言的头部两家里，修复执行闭环完成度领先**"，非世界范围的概念独占。
  • 机制层无原创（第 3 轮调研结论）：结构化建议（span+替换文本）、置信度分级（rustc 的 applicability 四级 vs Lom 三级）、迭代自动应用到不动点（cargo fix 的 fixpoint 循环）——机制三件套在 Rust 生态已完整存在多年；ESLint --fix/TS code fixes/Roslyn 为同类。Lom 的真实差异是四维组合：把修复闭环作为语言的存在理由（repair-native，非工具链附属）+ lom-diag/lom-fix schema 作为语言契约 + fix_corpus 修复语料回归网 + 高温 LLM 实测口径——该组合截至第 3 轮检索未见先例（相对 Rust/TS 生态的成熟度与规模，Lom 均为后来者——如实记录；详见 docs/archive/ 第 3 轮调研）。
  • "独有"的最终检验在发布后的外部反应：Lom 当前未发布，七轮独立审查均为内部委托（对抗深度真实、外部独立性相对）。

5. 如实标注：对方领先项

  • Vera：Z3 形式化契约验证（Lom 的验证形态是 golden/差分/自举/审查的工程证据链，非形式化证明）。
  • Zero：expected/actual 结构化诊断字段（Lom 目前揉在 message 文本；列为冻结期外的候选演进）；sub-10KiB 原生二进制（Lom 是 WASM 目标）。
  • MoonBit：生态与工具链规模（IDE/包管理/多目标成熟度，1.0 在途）；编辑器内生成时纠错路线。
