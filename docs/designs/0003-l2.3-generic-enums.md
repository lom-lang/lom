# L2.3-c2 泛型 enum 与内建 Result/Option 设计

- **范围**：在 L2 现有 untagged 值表示上编译内建 `Result`/`Option` 与泛型用户 enum 的构造、参数/返回、赋值和标量/枚举模式匹配；保持宿主 WASM 的行为对拍口径。
- **状态**：已按 RFC-0004 修订 12 交付（2026-09-23，仓库版本 v1.2.9）；verify_selfcomp 128/128 = 52 对拍 + 76 负例。
- **不改语言面**：不增加语法、关键字、诊断码或内建。内建变体沿用宿主保留的 `Ok=0`、`Err=1`、`Some=2`、`None=3` 索引，堆对象继续采用 c1 的 `[variant_idx:i32][arity:i32][payload:i64×n]`。
- **后续边界**：String/List/Map 载荷各随对应值表示批次；`?` 与显式 `return` 同属提前返回降级，待 return 批的块深度跟踪；枚举结构相等与显示仍留后续。对子集外形态给出编译期拒绝且不产 hex。

## 类型参数表示

编译期值类型 `vt` 保持无逗号、无 `@` 的可嵌套编码：非泛型用户枚举仍为 `en:Name`，泛型实例为 `en:Name{arg1;arg2}`；内建类型用 `en:Option{T}` 与 `en:Result{T;E}`。变体声明中的类型参数用 `tv:T` 模板占位，构造器尚不能确定的实例参数用 `?`。分隔符仅在最外层生效，解析器按花括号深度拆分，因此 `en:Tree{en:Option{i64}}` 无歧义。WASM 运行时表示始终是 i64 裸指针；类型参数只用于编译期校验与载荷读写宽度选择。

`@enum:<name>` 记录声明顺序的类型参数，`@variant:<name>` 记录变体索引、所属枚举与载荷类型模板。注册用户枚举时先登记全部枚举名/参数，再登记各变体，允许递归模板。内建 `Result`/`Option` 进入同一元数据路径，减少构造和模式的专门分支。

## 推断、上下文与模式

构造器逐载荷综合实际 `vt`，按模板递归统一同一类型参数。`Full(1)` 可推出 `Box<Int>`；`Pair(1, False)` 若两个字段共用 `T` 则编译期拒绝。零参 `None`、`Empty` 与单载荷 `Ok` 等未携带全部参数时留下 `?`；显式 let 注解、函数形参与返回类型可按结构兼容检查补全。块内直接赋值若补足此前未知的参数，类型预扫也按语句序细化其临时绑定。无上下文的未知载荷进入需要选 WASM 宽度的模式绑定时明确拒绝，绝不以 f64/i64 猜测。

模式匹配先验证变体所属枚举与 arity，再从被测实例 `vt` 代入模板载荷类型；成功测试变体索引后才读取载荷，继续沿用 c1 的页尾防护。裸 `?` 载荷不能选择读取宽度；`en:Tree{?}` 仍是已知 i64 指针，可在不读取未知内层载荷的模式中使用。类型预扫与真实发射分别使用 R79/R82 的块级绑定拷贝，臂绑定不泄漏。

## 验收

正例须穿宿主编译、L2 编译、hex 解码、两份 WASM 实例化与 stdout/rc 对拍：内建四变体、带注解的 `None`/`Ok`、泛型用户枚举单/多参数、重复参数约束、嵌套或递归实例、嵌套模式和页尾零参对象。负例锁具体拒绝原因与无 hex：错误类型参数数、未知类型、同一参数冲突、错构造 arity、错误模式/载荷类型、无上下文未知载荷、未支持的 String 与 `?`。
