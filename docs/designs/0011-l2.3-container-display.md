## 1. 背景与范围

L2.3 各批（String/List/Map/json/record）自始把容器显示面明确留本批：println(List)/println(Map)/println(枚举)/println(闭包)/println(record/tuple) 与拼接提升容器侧（`"x=" + <容器>`）目前全部编译期拒绝（负例 9 枚锁定文案）。RFC-0004 收官后这是 L2 侧最大的预留功能面——本批目标是**一次性收口**：六类值（ls/mp/en/rc/tp/cl）经 println/print 显示与拼接提升，宿主/L2 双侧行为一致（stdout+rc 逐字）。

**对拍基准（供料实测锚定，HEAD 双后端逐字节一致）**：
- List：`[1, 2, 3]`（String 元素无引号、Float 整值保 `.0`、嵌套递归）；
- Map：`{a: 1, b: 2}`（键字节序 = map_keys 序、多字节键、嵌套值递归）；
- 枚举：`Point` / `Circle(3)` / `Node(Leaf, 1, Leaf)`（零参裸名、载荷 `名(a, b)` 逗号空格分隔、递归枚举完整打印）；
- record：`{a: 1, b: x}`（字段声明序、无引号、嵌套递归）；
- tuple：`(1, a)`（**单元素 `(a,)`** 补逗号——宿主 rt_tuple_str 5625-5632 对齐解释器）；
- 闭包：`<闭包>`（宿主静态串）；
- 拼接：容器在任一侧均合法提升（`x=[1, 2]`、`[1, 2]=x`、`x=<闭包>`）。

**明确不在本批**：json 值参与拼接/算术（既有拒面维持——_Any 动态语义信任边界）；void/Unit 实参 println（R89 单列文案维持）；自引用 Map 环形显示（双侧均无限递归崩溃，行为对齐但属病态程序——登记边界、用例规避，见 §8）。

## 2. 现状与宿主参照系（读码供料结论，行号 @ 8a8d5a5）

### 2.1 L2 现状拒绝点（self_comp.lom）

- **comp_println**（5636-5688）：接受 i64/f64/st/i32(Bool，ibase≥4)/js；rc/tp 单列拒（5677-5681）、ls/mp/en/cl 兜底拒（5682）；comp_print_builtin（5606-5625）同面。
- **拼接提升 infer 拒绝**（4010-4030）：序 = cl/en（4013）→ ls（4016）→ mp（4019）→ rc/tp（4023）→ js（4026，维持拒）；comp_binary 发射侧（4930-4936）走 disp_code + st_concat。
- **disp_code**（4807-4824，18 行）：宿主 to_display 的标量子集——st 原样/i64→st_itoa/f64→st_ftoa/i32→select(intern true/false)/void→intern "()"。**容器臂不存在**——本批扩为全量 display_code。
- **可复用件**：js_of 族（js_conv_code 7661-7697 递归 ensure + "|" 键；js_of_list_body 7703-7736 遍历骨架；js_of_map_body 7743-7780 mp_keys 键序遍历）与容器显示 helper **结构同构**（特化键+递归 ensure+body 组装三步）；ensure_*_helper 四族（6808-7897）共享 extra 区与 reg_extra_fn（5853-5859）；intern_str_lit（5959-5979）data 段静态串；js_print（7596-7615）运行时 kind 分派打印的发射蓝本；scan_has_bool_display（9825-9856）+ ibase 兜底（5658-5670）双防线样板。
- **枚举显示三要素编译期全齐**：@variant:<name> 键（名字=键）+ .ret 属主（en:Name）+ variant_field_vts（4318-4341）实例化载荷 vt——缺的只是物化进 data + 显示体。

### 2.2 宿主蓝本（src/wasm_codegen.rs，对拍语义源）

rt_display = build_display（3093-3192）tag 分派：Enum→RT_ENUM_STR / Tuple→RT_TUPLE_STR / Record→RT_RECORD_STR / List→RT_LIST_STR / Closure→`"<闭包>"` 静态串 / Map→RT_MAP_STR；rt_print（2789-2886）容器兜底走 rt_display 转串再 print_str；拼接提升（build_arith 2486-2507）任一侧 Str → concat(display(l), display(r))。各 helper 行数：list_str 44 / map_str 62 / tuple_str 53 / record_str 61 / enum_str 76 / enum_print 68 / 变体名表 build_variant_table 20。解释器 to_display（interpreter.rs 245-302）逐分支对应（Map 键 sort() 字节序、Record 声明序、Tuple 单元素补逗号）。

### 2.3 关键机制差异（本批设计的两个根因事实）

1. **L2 untagged 无运行时 tag**：宿主 rt_display 是运行时 tag 分派（一个 helper 服务全部值）；L2 显示 helper 必须**编译期 vt 驱动特化**（per-vt body，与 ls_eq/js_of 同路线）。**枚举载荷 vt 依赖泛型实例**——`en:Option{st}` 与 `en:Option{i64}` 载荷显示通道不同，因此**枚举显示的特化键必须是完整实例 vt**（`disp_en|en:Option{st}`），不能只按枚举名；同枚举不同实例各发一体（显示用例量级下重复发射可接受）。宿主的单 helper 运行时分派在此无对应物——机制差异登记（实现自由度，行为对齐口径不受影响）。
2. **递归枚举显示自引用**：`en:Tree{i64}` 的 Node 载荷含 `en:Tree{i64}` 自身——disp_en body 递归 ensure 自己。L2 helper 注册即得 fidx（reg_extra_fn 追加前计算 ibase+nfun+n_extra_fns），body 组装时直接 call 自 fidx——**两遍式天然可行**（顶层 fn idx 先定的同型；宿主 finalize 回填机制在 L2 无需新造）。

## 3. 值通道（既定路线延伸，不设裁决点）

显示 helper 一律 `(i64 v) -> i64`（入参裸指针/值，返回 st 指针——对齐宿主 rt_display 形态）；println/print 经 print_st_hex（5627-5634）出口；拼接侧复用同一 display_code 后 st_concat。三入口（println/print/拼接）**单一事实源** display_code——宿主 rt_display 单点同构。

## 4. 裁决点 1：批次范围

- **甲 全量收口（六类 + 拼接同步）【建议】**：ls/mp/rc/tp/en/cl 六类显示 + print/println/拼接三入口全解禁，一次消除 9 枚预留负例（转正删除）。机制上六类共享 display_code 分派与 ensure 骨架；枚举（唯一新机制：变体名物化）增量可控（§2.1 三要素全齐）。
- **乙 五类先行（枚举独立小批）**：枚举名表机制风险隔离——代价：两次全量回归、"容器显示批收口"叙事拆两段、9 枚负例分两批转正。
- **丙 只 println/print 不做拼接**：拼接容器侧另批——代价：display_code 三入口的单点设计被拆散，负例族（neg_list_concat_promote 等 3 枚）滞留。

**建议甲**：机制同根（§3 单一事实源）、对拍基准已全量实测锚定（p1-p7）、分批只增加回归与登记成本。

## 5. 裁决点 2：枚举变体名物化机制

- **甲 per-实例特化 body 内联变体名 select 链【建议】**：disp_en|<完整实例vt> body 内——①该枚举全部变体名经 intern_str_lit 物化（编译期 map_keys(fns) 筛 .ret 属主，名字=键直接可得）；②idx（i32.load 偏移 0）→ name_off 的 select 链；③n>0 时 "(" + 逐载荷（偏移 8+8j，宽度按 variant_field_vts 实例化）递归 display_code + ", " + ")"；④载荷递归遇自身实例 → call 自 fidx（§2.3-2）。
- **乙 包级共享变体名表（宿主 build_variant_table 同构）**：data 段 `[name_off×n]` 数组 + 表偏移注入——需要新造 finalize 回填机制（L2 现无）+ global 导出面（宿主 lom_variant_table 供 harness 物化查名，L2 无消费方）。

**建议甲**：零新基础设施（intern/select 链/自递归 fidx 全是既有机制组合）；乙的两件新增机制在本批无收益。同枚举多实例时 select 链重复发射——特化键按实例去重后每实例至多一体，量级可接受。

## 6. 裁决点 3：预扫与深层流防御（Bool 批双防线先例的容器版）

显示通道依赖 String 设施（print_str/data）——ibase<4 的无字面量程序若含容器 println，与 println(Bool) 同型会发射越界 call。

- **甲 双防线【建议】**：①scan_has_display 预扫扩三类自然写法（println/print 直接容器实参 / 一层 let 绑定追踪 / 拼接两侧容器 vt）——沿 scan_has_bool_display（9825-9856）模式；②comp_println/comp_binary 的 ibase 兜底改容器族文案（深层容器流编译期拒、无坏 wasm）。
- **乙 只 ibase 防御**：实现最简，但无 String 字面量程序的容器 println 自然写法全拒——Bool 批 R85 同型缺口会在本批重演（十五审先例：预扫缺口的自然写法被拒曾开 P3）。

**建议甲**。注意：容器类型经签名/注解可得（vt 体系全程跟踪），预扫识别比 Bool 容易（Bool 需要"产 Bool 的表达式"识别，容器只需 vt 判定——scan 挂点直接查实参综合 vt，三层中前两层大概率一层即够；第三层（拼接）同 comp_binary 位点）。若实施中发现一层 vt 判定即全覆盖，预扫可简化——实施自由度，登记实际形态。

## 7. 裁决点 4：供料新发现——json_stringify 星面键序宿主双后端分叉（p8 实证）

供料实测发现（与容器显示正交的 json 面既有分叉）：Map 键含 **U+E000-U+FFFF（私用区/BMP 高区）与 U+10000+（星面）并存**时，json_stringify 键序解释器=Rust 字节序（E000 在前）、宿主 WASM=JS UTF-16 码元序（星面代理对 D83D 在前）——**双后端输出顺序不同**（println(Map) 显示不受影响，显示键序双侧同为字节序）；eval/现有用例界内未踩（规避面未含此条）；run_wasm.mjs 头部"已知差异"清单（23-25 行）未登记。

- **甲 开账 R94 登记挂账（P3）【建议】**：属宿主 json 面非本批行为面；修否另裁（可修 run_wasm.mjs 的 entries.sort 比较器为 UTF-8 字节序归一——宿主 harness 工具面一行级改动 + 对拍复验；与 map_remove 挂账同族并入宿主挂账清单）。
- **乙 随本批顺带修 harness**：一行比较器改动 + §11f 已知差异清单补登——但混入 L2 显示批不符"行为改动与文档成对"的批次纯度，且修复面属宿主双后端一致性（应与 map_remove 挂账同窗口统筹）。
- **丙 不登记**：不推荐——分叉已实证存在且已知差异清单漏登（登记完整性缺口，R86 同型）。

**建议甲**。

## 8. 方案技术设计（按甲/甲/甲/甲展开）

### 8.1 display_code（disp_code 的全量扩展，~40 行）

分派（编译期 vt）：`st` 原样 / `i64`→st_itoa / `f64`→st_ftoa / `i32`→select(true/false) / `void`→"()" / `ls{...}`→`ensure_disp_helper("disp_ls|"+elem)` / `mp{...}`→`disp_mp|"+V` / `rc{...}`→`disp_rc|"+rcvt / `tp{...}`→`disp_tp|"+tpvt / `en:...`→`disp_en|"+完整实例 vt / `cl`→intern "<闭包>" 静态串。返回 st（emit 序列：入参已在前述 ac 槽，call helper 后结果即 st）。

### 8.2 helper 族（ensure_disp_helper 家族 + 各 body）

- **disp_ls|T**（对齐 rt_list_str 44 行，预估 40-60 行）：Nil=0 哨兵遍历（L2 List 批惯例；宿主哨兵 9 是 tagged 形态差异，行为等价）；`"["` + 逐元素 display_code(elem) + `", "` + `"]"`——首元素前无分隔符的循环形态（宿主先判 Nil 出 `[]`）。
- **disp_mp|V**（对齐 rt_map_str 62 行，预估 50-70 行）：mp_keys（字节序既有）→ 逐键 mp_probe 取值 → display_code(值) → `"{"` + `k: v` + `", "` + `"}"`。
- **disp_rc|<rcvt>**（预估 40-60 行）：vt 字段序=声明序（record 批既定）→ 编译期偏移读（rc 访问同型）+ display_code → `"{"` + `名: 值` + `", "` + `"}"`；字段名 intern。
- **disp_tp|<tpvt>**（预估 40-60 行）：逐槽偏移读 + display_code → `"("` + … + `")"`；**单元素补 `","`**（宿主 `(a,)` 形态对齐）。
- **disp_en|<实例vt>**（预估 80-150 行，裁决点 2 甲）：§5-甲四步。
- **"<闭包>"**：零 helper——display_code 直接 intern 静态串返回。

**发射/去重/依赖序**：沿用 ensure_js_helper 家族三步（依赖先 ensure——disp_ls|T 依赖其 elem 的显示 helper + st_concat + print_str 设施；has_str 联动：任一显示 helper 被 ensure 即置 has_str/data 真——挂点在 ensure_disp_helper 首行与预扫）。

### 8.3 三入口接线

- comp_println：容器臂（rc/tp 5677-5681 与 ls/mp/en/cl 5682 两处拒绝）替换为 display_code(at) + print_st_hex；cl 同；ibase 兜底族文案更新（容器版）。
- comp_print_builtin：同面复用。
- 拼接：infer 拒绝臂（4013/4016/4019/4023 四处）删除（js 4026 维持）；comp_binary 的 disp_code 调用点换 display_code。

### 8.4 预扫（裁决点 3 甲）

scan_has_display：遍历 println/print 调用实参与 Add 两侧，综合 vt（复用既有 scan 综合通道——Bool 预扫同位）命中容器族即 has_str 置真；ibase 兜底双防线。实施时按 §6 注意事项定层次（vt 判定大概率一层即覆盖自然写法）。

### 8.5 自引用 Map 环形（登记边界，不做机制）

`map_set(m, "self", m)` 后显示——宿主双侧（解释器/WASM）均无限递归崩溃（栈溢出/V8 栈 trap），L2 同。行为对齐（都崩）但属病态程序：**登记边界 + 用例规避**，不做环检测（宿主也没有——对齐优先）。递归枚举/嵌套 List 无环（不可变构造），不涉。
