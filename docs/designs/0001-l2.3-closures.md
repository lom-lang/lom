## 1. 背景与范围

L2.3-a（控制流批）已交付 Bool/比较/逻辑短路/if/while/for(Int) 语句与块尾 if
表达式。下一批按 HANDOFF 约定处理**闭包与捕获**——它是后续所有堆分配批次
（enum 与 match / String / List / Map / json）的地基：本批引入的**堆分配器、
funcref 表、闭包值通道**三件基础设施将被全部后续批次复用。

本批目标（对拍口径与既有批次一致：**双产物行为级一致，stdout + 退出码逐字；
不做字节级一致**——RFC-0004 预设）：

1. 闭包字面量 `fn(x: Int) -> Int ... end` 作为表达式（含嵌套：闭包返回闭包）；
2. 捕获（创建时**值拷贝**语义——对齐宿主 WASM 后端，见 §2.3）；
3. 局部闭包值调用 `g(1)`；
4. 具名函数当值 `let f = double`（v0.4.2 宿主语义）；
5. 递归闭包（`let fact = fn(n) ... fact(n-1) ... end`）；
6. 任意表达式 callee 的调用（`make_adder(5)(10)` 形态——闭包嵌套写法）。

**明确不在本批**（按裁决点 B，见 §4）：`Fn` 类型注解（顶层 fn 签名携带闭包
参数/返回）、闭包值参与 println/比较/算术、闭包体内赋值捕获变量（宿主 WASM
侧本就编译拒绝，见 §8）。

## 2. 现状与宿主参照系

### 2.1 self_comp 现状（读码结论，examples/selfhost/self_comp.lom @ 3342 行）

- **值表示**：untagged——Int=i64、Float=f64、Bool=i32（L2.3-a 起）、
  Unit=void；编译期 `vt` 字符串体系（"i64"/"f64"/"i32"/"void"）静态跟踪
  每个槽（env: `Map<name, {slot, vt}>`；localvt: `Map<绝对槽, vt>`）。
- **模块布局**：五个 section——type（t0/t1 为 print 导入 + 用户函数
  t2+）、import（env.print_i64 / env.print_f64 共 2 个）、function、
  export（main）、code。**无 memory、无 table、无 global、无 data**。
- **函数索引空间**：0/1 = print 导入；顶层 fn 从 idx 2 起（collect_sigs
  两遍式：先收签名定 idx，再逐函数编译体）。
- **调用**：comp_call 只认 `ExIdent` callee，分派次序 println → fns
  直调（`call` 指令，R74 编译期校验 arity + 逐参 vt）；其余全拒。
- **闭包现状**：parse_closure 存在（AST 已有 `ExClosure(params, ret,
  body)`），infer_ex/comp_ex 落入 `_ =>` 兜底拒绝；负例 neg_closure.lom
  在 verify_selfcomp 锁定。

### 2.2 宿主参照系（读码结论，src/wasm_codegen.rs，Phase 7.3 起）

宿主闭包五件 + 两基础设施（**本方案的移植蓝本**）：

| 件 | 宿主实现（行号 @ HEAD） | 要点 |
|---|---|---|
| 自由变量分析 | `free_vars_block` / `fv_*` 家族（L6096-6250 区） | 按首次使用序确定性收集；块级作用域、for 变量独立作用域、闭包参数遮蔽、match 臂绑定 |
| 闭包体编译 | `compile_closure`（L5915） | 签名 `(i64 env, params...) -> i64`（宿主全 tagged 单类型）；local 0 = env；捕获表 `captures: Vec<(name, slot)>`；体内读捕获 = `lget(0)` + `i64.load(4+8*slot)` |
| 创建点 | `compile_closure` 尾部（L5968-6002） | env 对象 `[n: i32][v0..vn: i64]`（槽宽恒 8）+ 闭包对象 `[tslot: i32][env_ptr: i32]`（8 字节）；值 = 指针 tag TAG_CLOSURE |
| 调用 | `emit_closure_call`（L6045） | **先 args 暂存、后 callee 暂存**（对齐解释器求值序）→ tag 检查（非闭包 trap）→ 压 env → 参数 → 表索引 → `call_indirect` |
| 具名函数当值 | `emit_fn_value`（L6006） | 零捕获 shim：签名同闭包 `(env, params...) -> i64`，忽略 env 直调真函数；零捕获闭包对象 `[tslot][env=0]`；shim 按（name, tslot）去重复用 |
| 递归闭包 | `compile_stmt` StLet 特例（L1305-1319） | `let f = fn...f...end`：**预绑定 local → 编译闭包 → 闭包值入 local → 把真值补丁进 env 的自身槽位**（对齐解释器共享作用域语义） |
| 分配器 | `rt_alloc` = `build_alloc`（L2890） | `(i32 size) -> i32` bump allocator，全局 0 = hp；`new_hp > memory.size<<16` 时 `memory.grow`，失败 trap |
| funcref 表 | table + elem（L595-600） | `table_entries: Vec<funcidx>`（编译期收集）→ table section（min=max=n）+ elem section（active, table 0, offset 0）；**宿主恒发**（helper 内含 call_indirect） |

**callee 分派次序（宿主 L1995-2029，对齐解释器）**：println/print 与已导入
内建 → **具名函数直调（优先于同名闭包变量）** → 闭包变量（local 或捕获）
→ 任意表达式 callee（一律按闭包调用）。

### 2.3 捕获语义的参照系事实（三条，全部读码/档案核实）

1. **宿主 WASM = 创建时值拷贝**（HANDOVER §7.3 已声明的设计差异）。
2. **宿主解释器 = Rc 共享作用域**——创建后修改被捕获变量时宿主两后端行为
   不同（已知已登记差异，代码头注释声明）。
3. **宿主 WASM 闭包体内赋值捕获变量 → 编译报错**："WASM 编译：赋值给未
   定义变量"（Stmt::Assign 只查 `ctx.lookup`，不查 `capture_slot`——值拷贝
   语义下改拷贝无意义，宿主选择直接拒绝）。

**对拍含义**：verify_selfcomp 对拍双方都是 WASM 产物（宿主 build vs L2
build），宿主解释器差异不进入对拍面；L2 对齐宿主 WASM（值拷贝）即可。用例
可含"创建后修改被捕获变量"形态（两侧同为值拷贝，行为一致）；**不可含**
"闭包体内赋值捕获变量"形态（宿主侧编译失败，进负例）。

### 2.4 关键差异：宿主 tagged vs L2 untagged 对闭包的影响

宿主值单一 i64（低 4 位 tag），闭包类型条目恒为 `(i64×(n+1)) -> i64`——
**纯 arity 型签名，参数/返回类型无区分**，运行时 trap 兜底。
L2 untagged 下值通道多态（i64/f64/i32），`call_indirect` 的 typeidx 必须
**精确匹配**实函数签名（WASM 运行时类型检查按完整签名），因此 **L2 编译期
必须静态知道被调闭包的精确签名**（参数 vt 序列 + 返回 vt）。

这一差异是裁决点 A（值表示路线）与裁决点 B 中"`Fn` 注解推后"的直接根因：
`Fn` 注解在宿主是 `Type::Named("Fn")`——**不携带参数/返回类型信息**，经它
流过顶层 fn 签名后静态签名丢失，L2 无法生成正确的 call_indirect type。
（宿主无此问题——全 i64 单类型天然消除该信息需求。）

## 3. 裁决点 A：值表示路线（核心决策）

**甲：延续 untagged + 闭包值 = i64 裸指针（推荐）**

- vt 体系扩一个 `"cl"`（closure）；闭包值编码为 i64（堆地址零扩展），
  语义类型由编译期 vt 跟踪，与 Int 的区分纯静态；运行时兜底 =
  call_indirect 签名检查（typeidx 不符 trap）——编译期校验 + trap 双保险。
- env 绑定结构扩签名位：`{slot, vt}` → `{slot, vt, sig}`（sig = 形参 vt
  逗号串 + "->" + 返回 vt，如 `"i64->i64"`、`"i64,f64->f64"`；非闭包恒
  `""`）。调用点校验读 sig（R74 模式延续）。
- **优点**：① 不推翻 RFC-0004 修订 3 已验收的"untagged 值表示（实现
  自由度）"决策；② 存量 10 个对拍用例的 codegen 路径零改动（产物字节
  不变，回归面最小化）；③ 批次节奏延续——每批全量回归可对拍。
- **代价/风险**：后续 List/enum/json 批次到来时，动态值（异构容器、
  Any）需要自描述——本方案的演进位是**堆对象头加 tag 字段**（对象自
  描述，值仍是裸指针），而非宿主的值 tag 位。宿主 7.6a 的"tag 掩码耗尽
  重迁移"教训（§11 档案：tag 空间预留扩展位；掩码单一事实源）在对象头
  形态下天然规避（头字段是 i32，容量 2^32）。**主观推测**：List/Map/
  enum 批在编译期 vt 已可静态区分绝大多数通道，仅 json 等动态面需要头
  tag——届时单独设计，不动本批。

**乙：现在整体迁移 tagged i64（对齐宿主）**

- 全部值改 tagged（Int/Bool/Unit 直编码、F64 装盒堆对象、Str 数据段），
  闭包照抄宿主布局。
- **优点**：与宿主 wasm_codegen 同构，后续批次（enum/match/String/List/
  Map/json）全部"照抄宿主"即可；值通道单一。
- **代价**：本批工作量 = **重写 self_comp 现有全部 codegen**（算术/比较/
  逻辑/if/while/for/调用/println 的每条路径都变 tagged 分派），10 个存量
  对拍用例全链路重验；且 self_comp 自身跑在解释器上，每次算术装拆盒使
  编译速度显著变慢（行为对拍不涉性能，但开发迭代与 verify 时长变差）。
- **程序问题**：untagged 是 RFC-0004 修订 3 明文登记的已验收决策
  （"值表示（实现自由度）：untagged 原生 i64/f64"）；推倒它属于方向性
  变更，理应回 RFC 重议——本设计不推荐无实证压力下这么做。

**建议：甲。** 若未来某批次（主观推测：json 或异构 List 深水区）证明
untagged 路线代价失控，届时以实证回 RFC-0004 重议值表示，成本与收益
那时才有依据。

## 4. 裁决点 B：语法范围档位

- **B1 核心（基线范围）**：闭包字面量（含嵌套——闭包返回闭包/闭包参数
  是闭包）、捕获（值拷贝）、局部闭包值调用、具名函数当值、递归闭包。
  **无需任何类型注解扩展**（闭包值只在 let 局部流转，签名在字面量处
  静态已知）。
- **B2 任意 callee（建议纳入）**：`make_adder(5)(10)` 形态（callee 是
  ExCall 等任意表达式）。宿主支持（L2028-2029）；L2 侧 comp_call 的
  `_` 兜底臂改为 emit 闭包调用，增量小；对拍用例表达力显著提升（HOF
  嵌套闭包写法的自然形态）。**建议纳入。**
- **B3 `Fn` 类型注解（建议推后）**：顶层 fn 签名携带闭包参数/返回
  （`fn apply(f: Fn, v: Int) -> Int`）。宿主 `Fn` = `Named("Fn")` 无参型
  信息（§2.4）——L2 untagged 下 call_indirect 需要精确签名，`Fn` 注解
  静态丢失签名，支持它要么发明携带签名的注解语法（**语言面变化，v1.0
  冻结，需新 RFC——不可行**），要么运行时 trap 兜底（放弃编译期校验，
  违背 R68/R74 建立的"编译期严格校验"信任边界），要么签名推断（复杂
  脆弱）。**建议推后**：负例登记"Fn 类型注解留后续批次裁决"；本批对拍
  用例的 HOF 形态全部用嵌套闭包写法（`let make = fn(n) fn(x) x+n end
  end`——宿主同样支持，用例单份双编译无障碍）。

**建议：B1 + B2，B3 负例登记推后。**

## 5. 裁决点 C：捕获 mut 绑定

Lom 闭包"不支持 mut 捕获"是已知限制——但**宿主的限制在 typechecker 面**
（MUT002 warning，不拦截执行），宿主 WASM 后端本身**放行**捕获 mut 绑定
（值拷贝此刻值，行为良定义）。对拍用例若含 mut 捕获，宿主 build 过、
产物行为确定 → L2 放行即两侧一致。

- **放行（推荐）**：对齐宿主 WASM 行为；MUT002 是宿主检查器 warning 面
  事项，不在 L2 对拍基准内。对拍用例可含"let mut 计数器被闭包捕获"形态。
- **拒绝（保守替代）**：子集编译期拒 `let mut` 捕获，负例登记。代价是
  与宿主 WASM 行为面出现一条**本可避免的**子集外边界，且无安全收益
  （值拷贝语义下行为完全确定）。

**建议：放行（对齐宿主 WASM）。**

## 6. 裁决点 D：env 对象槽位布局

- **8 字节统一槽（推荐）**：env 对象 `[n: i32][v0..vn 各 8 字节]`，偏移
  恒 `4 + 8*i`（与宿主偏移公式一致）；i32 值（Bool）经
  `i64.extend_i32_s` 存 / `i32.wrap_i64` 取，f64 直接 `f64.store/load`。
  实现最简、偏移无状态计算、宿主公式直接平移。
- **紧凑混排（替代）**：按各槽真实宽度（i32=4/i64=8/f64=8）逐槽累加
  偏移。省内存（闭包 env 通常小，收益微），代价是偏移计算要携带逐槽
  类型状态、易错（WASM 非对齐访问合法但性能差，仍需对齐 padding 决策）。

**建议：8 字节统一槽。** 内存开销在本批场景（捕获表 ≤ 个位数）可忽略。

## 7. 方案甲技术设计（按推荐项 A甲/B1+B2/C放行/D统一槽展开）

### 7.1 值类型系统扩展

- `vt` 新增 `"cl"`；`vt_hex("cl") = "7e"`（WASM local/参数类型 = i64）；
  `vt_bt("cl") = "7e"`（块类型，闭包值语境的块尾 if 同理）。
- `ty_vt`：`TyNamed("Fn")` → Err（B3 负例文案："Fn 类型注解留后续批次"）；
  其余子集外类型维持现拒。
- env 绑定 `{slot, vt}` → `{slot, vt, sig}`（sig 仅闭包非空）。**构造点
  机械同步**（动工时 grep 清点：bind_params / StLet 绑定 / comp_for 的
  env set / 闭包参数绑定 / 捕获表填充等，预计 6-8 处）。
- `infer_ex` 新增 `ExClosure(params, ret, body)` 臂：参数/返回走
  `ty_vt`（子集外即拒）→ 综合签名串 → `Ok("cl")`（sig 由调用处从
  ExClosure 现场携带或经 env sig 读）。

### 7.2 模块布局扩展（预扫定布局 + 按需发射）

**预扫**：`collect_sigs` 后新增一遍 AST 扫描 `has_closure(prg)`（任一
`ExClosure` 或**具名函数当值引用**命中即真——后者 = 标识符出现在非调用
位置且不在 env 绑定内且在 fns 表内；动工时以最保守口径"任一 ExClosure
或任一 ExIdent 单独成表达式且名字在 fns"实现，宁可多发不可漏发）。

- **无闭包路径（存量）**：五 section 布局与现状**逐字节相同**——10 个
  存量对拍用例产物 hex 不变（动工验收时人工对比一次存量 hex 前后一致，
  作为"存量零改动"的一次性验证记录；不加常驻字节断言——L2 产物字节
  稳定性不是契约，RFC 口径是行为级）。
- **有闭包路径**：新增
  - **global**（1 个）：hp，i32，mutable，init = 8（**地址 0 保留哨兵**——
    吸收宿主 List Nil=空指针惯例，将来 List 批零成本）；
  - **alloc 内部函数**：`(i32 size) -> i32` bump allocator（宿主
    build_alloc 的指令序列平移：gget hp → 溢界判定 `new_hp >
    memory.size<<16` → `memory.grow` 失败 trap → gset → 返回旧 hp）；
  - **memory section**（min 1 页起步，alloc 自动 grow）；
  - **table + elem**：table（min=max=n，funcref）+ elem（active, table 0,
    offset 0, funcidx 列表）；仅当 `table_entries` 非空时发射（L2 无
    helper 内 call_indirect，比宿主"恒发"更精简）。

**函数索引空间（有闭包路径）**：0/1 = print 导入（不变）；2..2+nfun-1 =
顶层 fn（**不变**——两遍式天然免疫宿主 §7.3 的"闭包函数挤占索引空间"坑：
pass 1 先定全部顶层 idx，pass 2 闭包体从 2+nfun 起追加）；2+nfun = alloc；
3+nfun+ = 闭包体/shim（编译序追加）。

**type section**：t0/t1 = print（不变）；t2.. = 顶层 fn 签名（不变）；
按需追加 t_alloc = `(i32)->(i32)` + 闭包体/shim 签名（编译序）——闭包体
签名为 `(i64 env, p1:vt1, ...) -> rvt`（vt 按各参数，untagged 多态）。

### 7.3 自由变量分析移植（fv_* 家族 → Lom）

宿主 `fv_block/fv_stmt/fv_if/fv_pattern/fv_expr` 平移为 self_comp 的
Lom 实现（`FvState` 的 out/seen 双结构 → `List<String>` + `Map<String,
Bool>` 当集合；按首次使用序）。覆盖子集全语法（let/let mut/复合赋值/
赋值/if/while/for/return/裸表达式/闭包嵌套/比较逻辑算术/调用/括号/字面
量）；**match/record/字段/下标/try/range 等 AST 形态照宿主语义一并实现**
（编译期走不到——comp 侧仍拒——但 fv 正确遍历无害，避免后续批次二次
移植）。

### 7.4 闭包体编译

签名 `(i64 env, p1:vt1, ..., pn:vtn) -> rvt`；**local 0 = env**，参数从
local 1 起；捕获表进闭包体自己的 env Map（名字 → {slot: 虚位, vt, sig}
——**虚位**：捕获读取不走 local.get 而走 env 对象 load，编译分派按
"名字在捕获表"优先于"名字在 env Map"实现，二者不混槽）。体内：

- 读捕获：`i32.const 0` 不需要——`local.get 0`（env i64）+ `i32.wrap`
  + `i64.load/f64.load/i32.load (4+8*slot)`（按捕获槽 vt 选指令）；
- 读参数/局部：现路径不变；
- 调用 println/顶层 fn：现路径不变（fns 表在闭包体编译时可见）；
- 赋值：目标解析到捕获名 → **编译期拒绝**（文案对齐宿主："赋值给未
  定义变量 'x'（闭包捕获为值拷贝，不能赋值）"——括注是 L2 增强说明，
  宿主无括注；对拍不涉此形态，文案差异无对拍影响，负例断言 COMPILE-
  ERROR 即可）。

**实现复用**：comp_one_fn 参数化（params 起点、local 0 预留、ret_vt、
捕获表入参）——闭包体与顶层 fn 体共用块编译主干。

### 7.5 创建点序列（宿主 L5968-6002 平移）

```
① env 对象：size = 4 + 8*ncaps → call alloc → 存槽 e
   i32.store e[0] = ncaps
   逐捕获源（宿主 CapSrc 两态的 L2 对应）：
     - 创建点 env Map 命中（当前函数局部/参数，含外层闭包捕获值——
       L2 扁平 env 下经 Map 查槽即得）→ local.get <slot>；
   按 vt 存：i64 → i64.store；f64 → f64.store；i32 → extend + i64.store
   （统一 8 字节槽，裁决点 D）
② 闭包对象：size = 8 → call alloc → 存槽 p
   i32.store p[0] = tslot；i32.store p[4] = env_ptr
③ 闭包值：local.get p（i64，vt="cl"，sig 随 env 绑定记录）
```

**嵌套捕获链**（内层闭包捕获外层闭包的捕获值）：创建点 env Map 已含
外层捕获名（外层闭包体编译时捕获表进了它的 env Map——内层闭包在外层
体内创建，fv 分析出内层自由变量后，解析来源 = 外层 env Map 查得（外层
自己的 local 或外层捕获）——**外层捕获值此刻在 env 对象里而非 local**：
需先 `local.get 0 + load` 读出再存入新 env。宿主 CapSrc::Capture 分支
（L5986）即此；L2 对应实现 = 创建点解析来源时区分"外层捕获名 → 经
env[0] load 中转"与"本层 local → 直接 local.get"。（实现要点：外层
闭包体的 env Map 需携带"名字是本层 local 还是本层捕获"标记——sig
结构或独立 Map，动工时定，预计一处布尔位。）

### 7.6 调用编译（comp_call 扩展）

分派次序对齐宿主（§2.2 末尾）：

```
ExIdent(name):
  println → comp_println（不变）
  fns 命中 → 直调（不变；具名函数优先于同名闭包变量，对齐解释器）
  env 命中且 vt == "cl" → 闭包调用：
    ① args 逐个编译 → new_slot 暂存（求值顺序：先 args 后 callee，对齐宿主）
    ② callee（local.get <slot>）→ 暂存
    ③ 压 env：cl + i64.shr_u 4？——【untagged 无 tag 位】
       改为：i32.wrap cl → i32.load (4) → i64.extend（env ptr）
    ④ 压参数（按暂存序）
    ⑤ 压表索引：i32.wrap cl → i32.load (0)
    ⑥ call_indirect <typeidx=闭包体签名> 0x00
  env 命中但 vt != "cl" → 拒（"调用非闭包值"）
  两处都未命中 → "调用未知函数"（不变）
任意 callee（B2）：
  同 ①-⑥，callee 走 comp_ex 通用路径（vt 综合须 "cl"，否则拒）
```

**编译期签名校验（R74 模式延续）**：调用点读 callee 的 sig 串——arity
与逐参 vt 不符即 subset_err 拒绝（文案对齐 R74 风格："调用闭包第 i 参
类型不符（期望 X 得 Y）"）；返回 vt 由 sig 综合进 infer_ex（ExCall 的
callee 是闭包时返回 sig 的 rvt）。**运行时 call_indirect typeidx 检查
作为兜底**（编译器 bug 防线，正常路径不可达）。

### 7.7 具名函数当值（shim）

`let f = double`（ExIdent("double") 单独成表达式且不在 env、在 fns）→
emit_fn_value 平移：shim 签名 `(i64 env, p1:vt1...) -> rvt`（vt 取自
fns 摘要 prms/ret），体 = 参数直通 + `call <真函数 idx>`；零捕获闭包
对象 `[tslot][env=0]`；**按函数名去重复用**（宿主 shim_idx 模式——
L2 用 Map<name, tslot>）。sig = 该函数的 prms/ret 串。

### 7.8 递归闭包（预绑定 + 补丁）

宿主 L1305-1319 平移：`StLet` 且 value 是 `ExClosure` 且 fv 含绑定名 →

```
① 预绑定：new_slot(vt="cl") —— 先占槽（此刻值未定）
② 编译闭包（创建序列；捕获源解析"自身名"→ 预绑定槽，拷贝的是占位值）
③ local.set 预绑定槽 ← 闭包真值
④ 补丁：env 对象自身槽位写真值（local.get e + i32.wrap +
   local.get <预绑定槽> + i64.store 4+8*pos）
```

（宿主语义原样：递归闭包经 env 槽位补丁达成"引用自己"——值拷贝模型下
递归闭包的自身引用在捕获表内，补丁覆盖创建时的占位值。）

## 10. 信任边界登记（与宿主的已登记差异，本批新增三条）

R68（let 注解）/R74（调用校验）先例延续，本批三条进 RFC-0004 修订 8：

1. **校验 #6/#7（编译期拦 vs 宿主运行时 trap/print）**：宿主 tagged 运行
   时兜底（trap 或 "<闭包>" 打印）；L2 untagged 静态拦——**编译期严格
   校验收紧带**，与 R68/R74 同族。
2. **B3 推后（Fn 注解）**：宿主放行（签名信息丢失无害——全 i64）；L2
   拒绝（untagged 需精确签名）——子集外边界，后续批次裁决。
3. **println(闭包)**：宿主打 "<闭包>"；L2 拒——同 String 先例（neg_
   string：宿主合法 L2 拒，负例登记，用例避开）。

捕获语义本身**无新差异**：值拷贝对齐宿主 WASM；与宿主解释器的共享作用
域差异是宿主侧已登记的既有差异（§2.3），不因本批扩大。
