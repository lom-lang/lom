# L2.3 json 批设计方案

- **文档**：docs/designs/0007-l2.3-json.md
- **性质**：动工前置设计（HANDOFF 约定：涉值表示扩展的批次先出设计方案再动工——闭包 0001 / String 0004 / List 0005 / Map 0006 先例）
- **基线**：`a87020d` / v1.2.14（2026-09-26）；self_comp.lom 8633 行；verify_selfcomp 206/206 = 90 对拍 + 116 负例
- **状态**：**已交付（2026-09-26，RFC-0004 修订 22；仓库版本 v1.2.15）**——用户裁决"按建议执行"（路线甲+B1+B2+数字甲，三裁决点全按建议项）；verify_selfcomp 230/230 = 100 对拍 + 130 负例，存量 90 对拍用例 hex 逐字节不变，self_comp 9295 行。实施细化超设计的点：js 当 ls{js} 消费走 js_list_vt 归一 + list 位放行 + js_lguard 拆链守卫（kind!=5 trap）；校验扩至 14 形态（含 as 别名/一元负/Unit stringify 拒）
- **上游**：RFC-0004 修订 6/8/9/12/14/16/19/20（a 控制流 / b 闭包 / c1 枚举 match / c2 泛型 / String 批 / List 批 / Map 批 / 十六审整改）；st 布局与 ftoa 导入（String 批）、cons 槽 8B 按元素 vt 存取（List 批）、helper 特化与按需发射（各批）是本批复用件；**json 是 RFC-0004 L2.3 既定顺序 Map→json→包→return 的第二站**

---

## 1. 背景与范围

Map 批后 L2.3 剩余 json/包/return 三批。**json 批**的目标：让被编译程序能用
`from json import { json_parse, json_stringify }` 并消费其结果。

**本批目标**（对拍口径不变：双产物行为级一致——宿主 `lom build --target wasm`
vs L2 产物，stdout + rc 逐字；不做字节级一致）：

1. json_parse/json_stringify 双内建可编译可运行；
2. parse 结果的**核心消费形态**可用：`data.field` 动态字段访问（json_demo.lom
   / todo.lom 的实际写法）、array 结果经既有 list_get 消费（json_demo 的
   `json_parse("[1,2,3,4,5]")` 当 List 用）、标量节点 println；
3. `_Any` 类型注解位支持（todo.lom 的 `List<_Any>` 形态）；
4. import 注册堵 json 版"静默忽略"缺口（Map 批同款，随批必做不设裁决）。

**明确不在本批**（负例登记或后续批次）：record 字面量构造（`{id: ..., done: True}`
——ExRecord 编译属 record/构造批）；`println(js 容器)` 的 Record/List 显示
（容器显示批统一裁决——println(List)/println(Map)/println(枚举) 同族）；
`json_parse(file_read(..))` 的 file 批联动；包/return。

## 2. 现状与宿主参照系（读码结论，行号 @ a87020d，供料已逐处实证、规划者抽验三处）

### 2.1 Lom 语言的 Json 值模型（宿主）

**没有内建 Json 类型**——`json_parse: (String) -> _Any`（typechecker/builtins.rs
282-302），`_Any` 是渐进式通配（mod.rs 1175-1242），实际返回 **7 种既有 Value
的动态联合**（json.rs 头注释 4-15）：object→`Record`（键序保留）/array→`List`/
string→`Str`/number→`Int`（无小数指数）或 `Float`/true/false→`Bool`/null→`Unit`。
**消费靠动态分派**：`.name` 字段访问（解释器 Record 查找；宿主 WASM 按运行时
tag 分派，字段不存在 trap，wasm_codegen.rs 1832-1906）与 List 内建——**无 match
消费形态**（examples 实证）。stringify 接受任意值：标量直转、Map→object
（键排序）、List/Tuple→array、枚举→变体名/Debug 形态、闭包与 NaN/±inf→null
（json.rs 550-643）。

### 2.2 宿主 WASM 蓝本 = 宿主中介（Phase 7.7）

宿主 WASM 的 json 双内建**不走 wasm helper，走 env 导入**：`lom_json_parse
(ptr,len)->i64 tagged`（JS `JSON.parse` + materialize 物化任意 tag 堆值，用
产物导出的 `lom_alloc` 分配）；`lom_json_stringify(i64)->i64`（readVal 读堆 →
stringifyVal 镜像 json.rs 序列化）。**已登记双后端差异**（run_wasm.mjs 头注释
10-11，如实记录）：Int/Float 切分按 JS 值判定（"30.0"→Int 30，解释器按源语法
给 Float 30.0）；极端浮点最短表示 JS/Rust 有别。未登记风险点（供料排查）：
数字键对象键序（JS 整数样键按数值序重排 vs Rust 保插入序）、>2^53 整数
（JS 静默 F64 截断 vs Rust 报溢出）、深度守卫（Rust 100_000 vs V8 无限制）。

### 2.3 L2 现状拒绝点（self_comp.lom @ 8633 行）

| 位置 | 现状 |
|---|---|
| import 注册（collect_sigs 8310-8358） | 只有 string/list/map 三分支——**`from json import` 被静默忽略**（Map 批堵过的同款缺口） |
| ty_vt 层（2649） | `_Any`（TyNamed）→ "未知或子集外枚举类型 '_Any'"；Ty 枚举无 Json/Any 变体 |
| comp_call（4284） | json 内建 → "调用未知函数"（误导文案，import 忽略的下游） |
| ExField（infer 3472 / comp 3869 兜底） | **无 ExField 编译分支**——`data.name` 落"该表达式形态"拒 |
| ExRecord（同兜底） | record 字面量无编译分支（本批仍拒，负例登记） |
| comp_println（4614） | json 值 println 落容器显示拒（标量解包是本批新形态） |

### 2.4 核心难题（供料结论，规划者确认）

json_parse 返回**运行时才定型的动态联合**。宿主两头都靠 tagged 运行时承载
（Rust Value 枚举 / wasm 4 位 tag + 运行时分派的 `.field`）；**L2 的 untagged
表示没有这条通道**——string 批拒 string_to_int（Int|Unit 二元联合不可区分）
的同一根因，七倍放大。三条出路：harness 中介物化专用节点表示（甲）、产物内
自实现全流程（乙）、只做往返不做消费（丙）——见裁决点 1。

## 3. 裁决点 1：实现路线

- **甲：混合中介（建议）**——parse/stringify 走 **L2 harness 双导入**（JS 实现，
  与宿主 WASM 同语义=对拍基准零分叉），harness 物化 **JSON 专用节点树**
  `[kind:i32][payload 8B]`（经产物按需新导出的 alloc）；L2 侧只实现**消费分派**
  （vt `js` 不透明节点 + js_field 内部 helper + println 分派——内部 helper
  非新语言面，List/Map 批先例）。
  - 优点：parse 序列化重活复用 JS（对拍基准即 JS 语义）；产物增量最小
    （~500-800 行）；数字切分/键序等已登记差异天然对齐对拍基准。
  - 代价：harness +~150-200 行 JS（materialize 节点树 + stringifyVal 节点版，
    run_wasm.mjs 35-200 改写）；产物 export 按需加 alloc（has_json 预扫，
    存量程序发射零影响）。
- **乙：全 L2 自实现**——self_interp Part H（~780 行纯 Lom json 实现）算法级
  复用、wasm helper 化编译进产物。产物自包含（不依赖 harness 导入面变化）；
  但数字切分需在产物内模拟 JS 值判定（对拍基准是宿主 WASM 而非解释器）、
  深度守卫/溢出边界/`\uXXXX` 代理对全要自搬，Part H 依赖的 string_to_int
  路径需重写（Horner 累加），工作量 2-3 倍于甲。**不建议作为本批**（无对应
  收益——L2.4 自举闭环时产物仍跑在 node harness 上，不因自包含获益）。
- **丙：窄档往返**——只支持 `json_stringify(json_parse(s))` 直往返，消费面
  全拒。最小批，但覆盖不了 json_demo/todo 的任何实际消费形态，价值过低。

**建议：甲。**

## 4. 裁决点 2：消费与构造面档位

- **B1 核心消费（必含）**：
  1. `data.field`（ExField 在 js 值上编译 → js_field helper：object 节点逐键
     匹配取子节点；非 object 或键不存在 → trap，对齐宿主 `.field` 不存在 trap）；
  2. array 经既有 list_get/head/tail/for-in 消费（harness 物化 array 为
     `ls{js}` cons 链——元素槽 8B 存 js 节点指针，list 批 helper 零改动）；
  3. `println(js 标量节点)`：按 kind 分派打印（int→i64/float→f64/str→print_str/
     bool→bool 通道/null→"()"）；**println(js array/object) 落容器显示拒**
     （宿主打 Record/List display——容器显示批边界，信任边界登记）；
  4. `_Any` 注解位：ty_vt 层 `TyNamed("_Any")` → `js`（含泛型位 `List<_Any>`
     → `ls{js}`）；js 值的 let/参数/返回/闭包捕获/泛型载荷类型流。
- **B2 stringify 广参数（建议随批）**：宿主 `json_stringify` 接受任意值
  （42/"x"/1.5/true 标量、ls{}→array、mp{}→object 键排序）。甲路线下 harness
  只会序列化 js 节点——非 js 实参需**产物内先转 js 节点**（js_of 标量四枚
  小 helper + js_of_list/js_of_map 两枚转换 helper，中等增量）。不做则
  `json_stringify(42)` 这类形态在 L2 拒（信任边界登记）。
- **B3 record 字面量与 object 构造（明确不做）**：`{id: ..., done: True}` 是
  ExRecord 编译（record 批范围）+ todo.lom 完整闭环还涉 file 批——本批负例
  登记拒绝原因，留后续批次。

**建议：B1 + B2 同批**（B2 覆盖 json_demo 的 record 字面量 stringify 之外的
全部形态；B3 边界清晰）。

## 5. 裁决点 3：数字切分对齐

- **甲：对齐宿主 WASM（JS 值判定）——建议**：数值上整 → Int（"30.0"→Int 30），
  否则 Float。甲路线下 harness 物化即 JS 语义，**零实现成本天然对齐**；且
  designs/0006 已裁定 L2 对拍基准是宿主 WASM。代价：与宿主**解释器**分叉
  （已登记差异，非本批引入）。
- **乙：对齐解释器（JSON 源语法）**：有小数/指数 → Float。甲路线需在 harness
  物化时改判定（可行但引入与对拍基准的分叉——对拍用例须规避数字切分歧义
  输入，自缚手脚）；乙路线（全自实现）下反而是自然语义。

**建议：甲。**

## 6. 技术设计（按建议档 甲+B1+B2+数字甲 展开）

### 6.1 值表示与节点布局

- vt **`js`**（JSON 节点 i64 裸指针，编译期不透明——`vt_hex("js") = "7e"` i64
  载体）；`_Any` 注解位与 json_parse 返回都归一为 js。
- 节点布局 `[kind:i32][payload 8B]`：kind 0=null/1=bool/2=int/3=float/4=str/
  5=array/6=object。payload：bool→i32 扩宽、int→i64、float→f64 槽、
  str→st 指针、array→**ls{js} cons 链指针**（元素=js 节点指针，cons 槽 8B
  规则复用）、object→**键值对序列指针**（保插入序——**不用 Map 承载**：
  Map 键序重排会与宿主 Record 插入序 stringify 分叉；承载形态实施定：
  kv 数组或 cons 链，每条目 [key_st:i64][val_js:i64]）。
- heap_on 预扫扩：json 内建调用/`_Any` 注解/js vt 进 needs_heap 保守口径。

### 6.2 模块布局与导入

- 按需发射 `has_json` 预扫（json 内建 import 或 `_Any` 注解出现）：import 追加
  `env.lom_json_parse (i32,i32)->i64` / `env.lom_json_stringify (i64)->i64`
  （ibase 续扩，全 idx 参数化——has_str 先例）；**export 追加 alloc**
  （harness 物化分配用，宿主 lom_alloc 先例）。存量程序（无 json）发射逐字节
  不变——全量对拍验收项。
- import 注册：collect_sigs 加 `module == "json"` 分支 + `js_builtin_entry`
  （双内建签名；**未知名报"未知内建 'json.<name>'"**——堵静默忽略，Map 先例）。

### 6.3 编译路径

- `comp_call` json 分派：parse 实参 vt 须 st（否则编译期拒）→ 取 [len][bytes]
  → call 导入 → 结果 vt js；stringify 实参 vt js 直 call；B2 下非 js 实参先
  发射 js_of 转换（按实参 vt 特化 helper 选择）再 call。
- **ExField 编译（新）**：被访值 vt==js → call `js_field` helper（object 逐键
  st_eq 匹配→子节点指针；miss/非 object → unreachable trap）；vt 非 js 的
  ExField 维持现拒（record 批边界）。infer 侧 ExField(js) 返回 js。
- **println(js)**：comp_println 加 js 分派——发射按 kind 的运行时分派序列
  （kind 2/3/4/1/0 五路 → 各 print 通道；kind 5/6 → "容器显示留后续批次"
  拒——**编译期无法预知节点 kind，需运行时检测**：发射 test kind + 命中容器
  kind 走 trap 携带说明（对齐"不留坏 wasm"——运行时 trap 是宿主字段不存在
  同款行为面）。实施细节：或经 `js_print` helper 内聚分派+trap）。
- **B2 js_of 家族**：`js_of_i64/f64/i32/st`（构造标量节点，产物内 8-16 行
  helper）；`js_of_list|T`（逐元素转 js 再 cons 成 ls{js} 后包 array 节点——
  元素按 T 递归选 js_of，特化键规则同 List HOF）；`js_of_map|V`（map_keys 序
  逐键取值转 js 组 kv 序列——**键序=map_keys 字节序=宿主 stringify Map 键
  排序语义**，对齐而非分叉）。en/cl 值元素拒（mp_eq 同族负例）。

### 6.4 harness（run_selfcomp.mjs）

- `lom_json_parse(ptr,len)`：`JSON.parse` → 递归物化节点树（经导出的 alloc；
  数字按 JS 值判定建 int/float 节点——裁决 3 甲天然成立）→ 返回根节点指针。
- `lom_json_stringify(node)`：读节点树 → 序列化（**移植 run_wasm.mjs
  stringifyVal 的 escStr/键序/Debug 形态逻辑**到节点版；float 经 `String(v)`
  与宿主 WASM 同源）→ 经 alloc 物化 st 返回。
- parse 失败：JS 异常 → wasm trap → rc 1（宿主 WASM 同款，行为级对拍口径下
  stdout+rc 一致）。

| # | 形态 | 文案要点 | 宿主参照 |
|---|---|---|---|

| 2 | 未知 json 内建名 | "未知内建 'json.<name>'"（堵静默忽略） | — |
| 3 | `json_stringify` 非 js 且 B2 外形态（en/cl 值的 ls/mp） | "stringify 暂不支持 枚举/闭包 值元素" | 宿主 Debug 形态合法——信任边界 |

## 8. 信任边界登记（本批新增，进 RFC 修订）

1. **json_stringify 广参数档**（裁决 2）：en/cl 值元素编译期拒（宿主 Debug
   形态合法）；record 字面量/todo 重建形态拒（B3——record/file 批）。
2. **println(js 容器)**：运行时 trap 携带说明（宿主打 display——容器显示批
   统一边界，println(List)/println(Map) 同族）。
3. **数字切分对齐宿主 WASM**（裁决 3 甲）：与宿主解释器在 "30.0" 类输入上
   分叉——**宿主既有已登记差异**（run_wasm.mjs 头注释），L2 站对拍基准侧。
4. **parse 失败路径**：双侧 rc1 + stdout 一致（解释器的 RuntimeError 消息文本
   不进对拍口径——行为级口径既有约定）。
5. **`_Any` 收窄**：宿主 `_Any` 兼容任意类型参与运算；L2 的 js 是不透明节点
   vt，算术/比较/拼接显式拒（校验 #7）——string_to_int 拒绝先例的系统性登记。
