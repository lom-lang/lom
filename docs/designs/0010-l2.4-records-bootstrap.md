## 1. 背景与范围

L2.4 供料证明：self_comp 源码无法被现 L2 编译——**record/tuple 语言面缺口是第一序障碍**
（record 字面量 263 处/字段访问数百/tuple 访问 33 处/签名与枚举载荷注解全在编译面外），
file/env 四内建 import 是第二道，栈深是第三序。本设计按路线甲分两段交付：

- **第一段（record/tuple 编译子批，L2.3 第十一批）**：补齐 record/tuple 的 L2 编译面
  （这是语言面既有真实缺口——用户程序同样受益，非为自举特设）+ file/env 四内建
  宿主中介导入 + math/io 死导入放行；
- **第二段（L2.4 自举闭环）**：self_comp 编译自身产 wasm → 该 wasm 再编译示例
  程序——三层自证（对齐 L1 的 8.4 模式），自施加（wasm self_comp 编译 self_comp
  源码）作为 L1 先例的加分式收尾（时间允许则做）。

**对拍口径不变**：双产物行为级一致（stdout + rc 逐字）。

## 2. 现状与宿主参照系（读码供料结论，规划者确认）

### 2.1 宿主蓝本（src/wasm_codegen.rs）

- Record = tag 8 `[n:i32][(name_off,val) 12B/字段]`（L1800）；Tuple = tag 7
  `[n:i32][elems 8B]`（L1773）；字段查找是**运行时 name_off 比较**（tagged 世界
  类型不自描述）。7.6a 批含 e2e 测试（L6622-6684）。
- file/env 走宿主导入：`lom_file_read (i32,i32)->i64`、`lom_file_write/append
  (i32,i32,i32,i32)->i64`、`lom_file_exists (i32,i32)->i64`、`lom_env_args
  ()->i64`（L750-771）；JS 实现在 run_wasm.mjs L228-268（tagged 形态——移植需
  去 tag 位）；math 是内联指令非导入；io 显式导入等价 no-op（L480）。

### 2.2 L2 缺口（供料四道闸门 + 自举实测）

| 闸门 | 位置 | 现状 |
|---|---|---|
| 枚举载荷 tuple/record 注解 | register_enums → ty_vt 兜底 L2736 | **实测首错**（11.3s 处） |
| import file/math/env/io | collect_sigs L9115 | "未知模块"拒（4 行全中） |

harness materializeNode array 物化逐字节同构（args 移植可直抄）**。

## 3. 值表示（沿 untagged 先例延伸，不设裁决点）

- **vt 编码**：record `rc{name:vt;name:vt}`（**字段名进 vt**——record 是结构
  类型，字段序与名字都是类型组成部分；字段名是标识符（字母数字下划线），
  `:` 在既有 vt 字符集（`;`/`{}`/`|`/`@`/`en:` 前缀）未占用、不冲突）；tuple
  `tp{vt;vt}`（位置化无字段名）。示例：`rc{n:i64;t:st}`、`tp{i64;st}`、
  `Map<String, rc{...}>` = `mp{rc{...}}`、闭包 sig `rc{...}->i64`。
- **堆布局（untagged，先例延伸）**：record/tuple 对象 `[n:i32][field 8B × n]`
  ——字段槽 8B 按字段 vt 定宽存取（f64 直写/i32 扩缩/其余 i64——**cons 槽与
  Map 桶 val 槽完全同型的第三应用**）；WASM 值 = i64 裸指针。
- **字段访问**：untagged 下类型编译期已知——**纯偏移读取**（名字→序号→
  `8+8×idx` 偏移 + 宽度补码），无宿主的运行时 name_off 比较。字段序的确定：
  以**注解序为准**，无注解时以字面量构造序（类型流中同字段集的序合并规则：
  首见序固化——self_comp 源码同一 record 形态写法一致，实测口径）。
- **tuple 访问**：`.0/.1/.2` 按位置偏移（ExField 的 Int 字段名形态——parser
  产 ExField(name="0") 还是独立形态，实施时按 AST 实况接）。
- **vt_hex**：`rc{...}`/`tp{...}` 均为 `7e`（i64 载体）。
- **vt_merge/vt_compatible**：扩 `rc{`/`tp{` 前缀（嵌套拆分复用）。
- **heap_on 预扫**：record/tuple 字面量构造进 needs_heap 保守口径。

## 4. 编译路径

- **ty_vt 层**：`TyRecord(fields)` → `rc{...}`（逐字段 ty_vt 递归）；`TyTuple(tys)`
  → `tp{...}`；枚举载荷注解与函数签名注解经既有 ty_vt/ty_vt_with_params 路径
  自然解锁（L2736 兜底面收窄）。
- **infer_ex**：`ExRecord(fields)` → 综合字段 vt 表产 `rc{...}`（字段值经
  infer_ex 递归）；`ExTuple` → `tp{...}`；`ExField`：被访值 vt 为 `rc{...}` →
  查字段序产字段 vt（未知字段名编译期拒）；`tp{...}` → `.N` 产位置 vt（越界
  拒）；vt 为 js 走既有 json 分支（不动）。
- **comp_ex**：`ExRecord` → `lom_alloc(4+8n)`（对齐 8）+ `store n` + 逐字段
  求值存槽（宽度定发）；`ExTuple` 同构；`ExField(rc)` → `comp_ex(对象) +
  载荷读`（wrap + 偏移 load + 补码——**js_field/mp 桶读同族件**）；
  `ExField(tp)` 同构按位置。
- **构造序与注解序一致性校验**：字面量字段集与注解字段集不符（缺/多/序）
  → 编译期拒（R68 注解一致性路线）；同名异序视为不同类型拒（结构类型语义）。
- **println/比较/拼接**：record/tuple 显示与相等比较**明确拒**（容器显示/
  相等批边界——self_comp 源码不用 println(record)（供料：println 47 处全是
  诊断输出）；record 相等用法待实施时 grep 确认，若 self_comp 源码使用则
  rc_eq 结构递归随批（ls_eq/mp_eq 同族），否则负例登记留后续）。
- **let 解构 `let (a,b) =`**：供料 0 处——不支持维持现拒（负例域不变）。

## 5. file/env/math/io 内建（宿主中介，json 批甲路线先例）

- **import 白名单扩**：collect_sigs 分派加 `file`（file_read/file_write/
  file_append/file_exists 逐名）/`env`（args）/`math`（sqrt/abs/min/max——
  **死导入放行**：self_comp 只 import 未调用 sqrt；放行=注册摘要但不发调用
  代码？不对——放行指 import 语句不拒；若用户真调用 sqrt 则需编译支持。
  self_comp 自举只需 import 放行。**最小面**：math 四名走 f64 内联指令编译
  （宿主蓝本 L2142-2185——sqrt=0x9f f64.sqrt 等单指令，成本极小，顺带支持
  调用面））/`io`（println/print——println 已支持，import 语句 no-op 放行
  对齐宿主 prelude 语义）。
- **file/env 四内建走 harness 导入**（json 先例）：has_fileenv 预扫（file/env
  import 出现即发）→ import 追加 `lom_file_read (i32,i32)->i64`（返回 st 指针
  ——untagged 裸指针，harness writeStr 直出）/`lom_file_write/append
  (i32,i32,i32,i32)->i64`（返回 0=void 语义；self_comp 未用返回值——void 签名
  照 json 前例按需）/`lom_file_exists (i32,i32)->i32`（Bool i32 0/1）/
  `lom_env_args ()->i64`（返回 ls{st} cons 链头指针——**harness 物化直抄
  materializeNode array 分支**：writeStr + 16B cell 裸指针 cons、Nil=0）。
  String 实参拆 (ptr+4, len) 两路（print_st_hex 同款）；args 返回 vt `ls{st}`。
- **harness（run_selfcomp.mjs）+4 导入**：file_read/file_write/file_exists/
  env_args（fs 真实 IO——self_comp 驱动层的 file_write 写 hex 文件、file_read
  读源码，harness 落真实文件系统，路径经参数传入；run_selfcomp.mjs 需扩
  argv 透传：node run_selfcomp.mjs <wasm> [args...] → wasm args()）。

## 6. L2.4 自举闭环（第二段）

- **验收器**：tools/verify_selfcomp.py 加 `--bootstrap` 模式（结构借
  verify_selfhost.py --wasm 三段）：
  - **① 自举层**：宿主跑 `self_comp.lom -- self_comp.lom self_comp.hex` →
    hex2wasm → wasm self_comp（COMPILED 行 + hex 非空即过第一关）；
  - **② 三层对拍**：wasm self_comp（node --stack-size=60000 起步实测，
    timeout 600-900s）编译对拍用例**代表子集**（预计 15-25 个：覆盖各批核心
    形态——控制流/闭包/枚举/String/List/Map/json/return 各抽 2-3 + 包项目 1
    经 pkg-expand 展开单元；wasm self_comp 的驱动层 argv 传第三参包名）→
    产物 hex → hex2wasm → node 跑 → 与宿主直接编译同用例的产物对拍
    （stdout+rc）；**编译输出对拍**（三层：两份 wasm 的运行行为一致 +
    COMPILED 成功）。
  - **③ 自施加（加分项，时间允许）**：wasm self_comp 编译 self_comp.lom
    源码 → hex → 与宿主编译的 self_comp.hex **逐字节对拍**（L1 selfapply
    先例）——确定性编译器应逐字节一致（若不一致则行为级对拍降级并登记）。
- **栈深**：60000 起步实测爬升（L1 先例 10^5 层已验证；超限如实降级子集
  口径——RFC-0004 Unresolved 5 的原预案仅在此场景启用）。
- **CI**：--bootstrap 模式本地与交接验收跑；CI 加固定子集冒烟（1-2 用例，
  防 wasm 层回归）——**CI 时长敏感（wasm self_comp 单次编译分钟级），
  CI 只跑最小冒烟**，全量 --bootstrap 留本地/交接。

## 9. 信任边界登记（进 RFC 修订）

1. record/tuple 的显示与相等比较拒（容器显示/相等批边界——同 List/Map 族）。
2. `let (a,b) =` 解构维持拒（self_comp 源码零使用；负例域不变）。
3. 字段访问是编译期偏移（untagged 静态类型）——宿主 tagged 运行时 name_off
   比较的语义等价面（类型系统保证下）；动态 record（js 值）走 json 批既有
   分支不受影响。
4. wasm self_comp 编译耗时分钟级——CI 只冒烟，全量 --bootstrap 本地/交接。
5. 栈深 60000 起步实测；超限按 RFC-0004 Unresolved 5 如实降级（仅此场景）。

## 12. 开放问题（实施中定）

1. ExField 的 tuple 索引 AST 形态（字符串 "0" vs 独立节点——按 parser 实况接）；
2. self_comp 源码的 record 相等用法 grep（有用则 rc_eq 随批，无用留后续）；
3. wasm self_comp 的驱动层 argv（harness 透传形态）与 file_write 落盘路径

5. 自施加 ③ 的逐字节一致性（确定性编译器应成立；浮点字面量解析路径若有余
