## 1. 背景与范围

L2.3 已交付 a/b/c1/c2/String 五批。剩余批次 List / Map / json / 包 / return 中，**List 批**是
下一个：String 批交付时明确挂到本批的两项（split 返回 List、for-over-String 与 for-List 同属
迭代语义）都在这里收口。List 是 Map/json 的数组侧前置（json array → List），b 批的堆分配器、
8 字节统一槽约定与 c2 的嵌套 vt 编码是本批复用件。

**本批目标**（对拍口径不变：双产物行为级一致——宿主 `lom build --target wasm` vs L2 产物，
stdout + rc 逐字；不做字节级一致）：

1. List 值流过 L2：构造（list_cons/list_empty/range `a..b`/split）、10 个 list 内建、
   for-in-List 迭代、List 在 let/参数/返回/赋值/if/match Binder/闭包捕获/泛型载荷
   （`List<T>` 注解、`en:Box{ls{i64}}`、`Result<Int, List<Int>>`）的类型流；
2. HOF 三件（list_map/list_filter/list_fold）——闭包与具名函数当值作 `f`；
3. for-over-String（0004 既定挂账，与 for-in-List 同批把 `comp_for` 补成宿主同款三向分派）。

**明确不在本批**（负例或后续批次）：`println(List)` 与拼接提升的 List 侧显示（宿主打
`[a, b]`——与 println(闭包)/println(Enum) 同边界，留容器显示批统一裁决）、Map/json/包/
return、List 的 `<`/`>` 等大小比较（宿主跨类型 trap，本批不做）、List 模式（宿主 Pattern
只有 Lit/Binder/Wildcard/Variant，**无 List 模式**——不涉）。

## 2. 现状与宿主参照系（读码结论，行号 @ 20a29a3）

### 2.1 L2 现状（self_comp.lom 6578 行）

前端已就绪：`ExRange` 解析（L1796）、fv/scan 对 ExRange 的遍历（L5213/L5306）、
`TyGeneric("List", [T])` 类型形态（与宿主一致，self_comp 的 Ty 枚举无独立 TyList）。
编译侧拒绝点：

| 位置 | 现状 |
|---|---|
| `ty_vt_with_params`（L2580 TyGeneric 分支） | `List` 不在 `@enum:` 元数据 → "未知泛型枚举类型 'List'"——**签名层 List<T> 进不来** |
| `infer_ex`（L3048） | `ExRange` 落 `_ => Err("该表达式形态")` |
| import 注册（L6241/L6291 两遍式） | 只处理 `module == "string"`——`from list import {...}` 的内建全未注册 → "调用未知函数" |
| `comp_for`（L5743） | `it != "i64"` 即拒："for 迭代仅支持 Int（String/List 留后续批次）" |
| `comp_println`（L4001） | "println 只接受 Int/Float/String/Bool（枚举显示留后续批次）"——List 落拒 |

现存 List 相关负例 2 个（本批处置见 §8）：neg_for_string（for-String 拒）、
neg_split_list（split 拒——文件头注释"随 List 批交付"）。

注意：self_comp **自身**作为 Lom 程序大量使用 7 个 list 内建（L31 导入表：empty/cons/
head/tail/is_empty/length/get——前端复用 self_interp 使然）。它跑在宿主解释器上，与
"编译侧支持被编译程序用 List"是两回事，本批不动 self_comp 自身的写法。

### 2.2 宿主参照系（src/wasm_codegen.rs + interpreter.rs + typechecker）

- **值表示**：tag 9（TAG_LIST）。**Nil 是 tagged 立即值 9**（`(0 << 4) | 9`，即指针 0）；
  **cons 单元 = 堆上 16 字节 `[head: i64][tail: i64]`**（rt_cons / build_cons L5148：
  alloc 16 → store 0/8 → 或 tag）。tail 是 Nil 或下一 cons 的 tagged 值——单向链表。
- **内建编译**（调用点 L2236-2307）：
  - `list_empty()` → **内联** `i64.const 9`（Nil）；
  - `list_is_empty(xs)` → **内联** `xs == 9` 取 Bool；
  - `list_head/tail(xs)` → **内联** 空表判（== 9 则 unreachable trap）+ `load 0/8`；
  - `list_length/get`、`split` → RT helper（rt_list_len L5181 遍历计数；rt_list_get L5211
    越界 trap；RT_SPLIT）；
  - `list_cons(h, xs)` → `call RT_CONS`；
  - `list_map/filter/fold` → RT helper + `emit_helper_call_closure`（tagged 单型
    `(i64, i64) -> i64` call_indirect 调 f）；
  - `range a..b`（ExRange 编译 L1938）→ `call RT_RANGE`（build_range L5159：v 从 end 递减
    cons 到 start+1，左闭右开）。
- **for-over-List**（L1471-1505）：迭代槽复用为当前 cons 指针；`== 9`（Nil）终止；
  循环变量 = `load 0`（head）；步进 = `load 8`（tail）。
- **for-over-String**（L1418-1469）：cnt = 字节偏移，limit = len；循环变量 =
  `RT_STR_CHAR_AT(s, off)` **物化单字符 Str**；步进 = 从物化串头 `i32.load 0` 读字节数。
- **结构相等**：`==` 的 tag 分派（L2704）List → `RT_LIST_EQ`（build_list_eq L5846：双指针
  齐步遍历，head 走 `RT_EQ` 递归——元素跨类型恒 false，长短不等 false；`!=` 取反）。
- **显示**：`rt_list_str`（L5534）display 为 `[a, b]`（元素递归 display）——println 面。
- **HOF 谓词语义**：`list_filter` 的 f 结果走 `RT_TRUTHY`（L73 注释"非 Bool 时 trap"）；
  解释器侧 `is_truthy()?` 非 Bool 同为运行时错误——两后端一致。
- **解释器语义**：Rc cons 不可变（list_cons O(1) 返回新表）；list_get 越界 / head、tail
  空表 → 运行时错误；list_map/filter/fold 的 f 可为闭包字面量或具名函数（v0.4.2+ 当值）。
- **typechecker**：`List<T> = Type::Generic("List", [T])`；内建签名一律 `List<_Any>`
  **元素类型跟踪 deferred**；`a..b` → `List<Int>`（两端非 Int 报 TYPE001 warning）；
  `for x in xs` 把 `List<T>` 的元素类型推给循环变量（§4.4）。

### 2.3 关键差异：宿主 tagged vs L2 untagged 对 List 的影响

与闭包批（0001 §2.4）/String 批（0004 §2.3）同型，但多一层**元素多态**：

1. **cons 槽宽**：宿主 tagged 下槽里存的是单一 tagged i64（f64/Str 等已装盒），无元素类型
   信息需求。L2 untagged 下值通道多态（i64/f64/i32/st 指针/en 指针/cl 指针），cons 槽
   8 字节统一，**读写按元素 vt 还原**：f64 → `i64.reinterpret_f64`(0xbd) 存 /
   `f64.reinterpret_i64`(0xbf) 取（WASM 标准 opcode，纯实现面）；i32(Bool) → extend/wrap；
   其余（i64/st/en/cl 皆 i64 载体）直存——**与闭包 env 槽（0001 裁决 D"8 字节统一槽"）
   完全同型**。
2. **HOF 的 f 签名**：宿主 helper 单型（f 一律 `(i64,i64)->i64` call_indirect，运行时
   兜底）。L2 call_indirect 需精确 typeidx → **helper 按闭包签名特化**（§7.2）。
3. **元素类型跟踪深度**：宿主 deferred（`List<_Any>`，get/head 返回 `_Any`）。L2 vt 体系
   精确——`ls{T}` 跟踪到元素（否则 head/get 的读出宽度无从选择，精确跟踪是 untagged 的
   **必然**而非可选）。

## 3. 值表示（既定路线延伸，不设裁决点）

沿 designs/0001 裁决 A甲 untagged 路线自然延伸（0001 §7.2 既定伏笔："global hp init 8
——地址 0 保留哨兵——吸收宿主 List Nil=空指针惯例，将来 List 批零成本"），无方向性变更：

- **vt 编码**：新增 `ls{T}`——嵌套花括号，与 c2 的 `en:Name{arg;arg}` 同族。示例：
  `ls{i64}`、`ls{f64}`、`ls{st}`、`ls{i32}`、`ls{en:Color}`、`ls{ls{i64}}`（嵌套）、
  `en:Box{ls{i64}}` / `en:Result{i64;ls{st}}`（泛型载荷）、闭包签名 `ls{i64}->i64`
  （sig 串按逗号/@分隔——`ls{...}` 不含这两个字符，无歧义；c2 的花括号深度拆分规则
  天然覆盖）。
- **WASM 值 = i64**：**Nil = 0**（heap 地址恒 ≥ 8，`i64.eqz` 判 Nil——宿主 Nil 立即值 9
  的去 tag 等价物）；cons = 堆地址（≥ 8）。与 Int 的区分纯编译期 vt，与 "cl"/"st" 同型。
- **cons 单元布局**：`[head: 8B][tail: 8B]`（剥 tag 后偏移 0/8，与宿主一致）。
- **元素存取**：按元素 vt（§2.3-1 的 reinterpret/extend 规则）。
- **heap_on 预扫扩**：任一 list 内建调用 / range / split / for-in-List / `ls` vt 注解 /
  `ls` vt 闭包捕获 → needs_heap 命中（heap_on 防御 L4170 保留 fail-safe）。

## 4. 裁决点 1：批次范围档位

List 面横跨"值通道 / HOF 特化 / 迭代补全"三个工作量级，拆档如下：

- **B1 值通道核心（基线，必含）**：`ls{T}` 类型流（ty_vt/infer/comp/scan 预扫/let 注解
  一致性/赋值/if/match Binder 载荷/闭包 sig 与捕获/泛型载荷解禁）；7 个非 HOF 内建
  （list_empty/cons/head/tail/is_empty/length/get——empty/is_empty/head/tail 调用点内联，
  对齐宿主；length/get 走 helper）；range 表达式 `a..b`；**split 解禁**
  （neg_split_list 转正，返回 `ls{st}`）；for-in-List（迭代变量 vt = 元素 vt）；
  空表 head/tail 与 get 越界的 trap 语义（双侧运行时一致，不属差异）。
  `list_empty()` 无参无上下文 → 返回 `ls{?}`（c2 未知参数 `?` 机制复用）：由
  `list_cons(5, empty)` 结构补全为 `ls{i64}`、由 `let xs: List<Int> = list_empty()`
  注解补全；无上下文裸 `ls{?}` 进入需宽度的位置（head/get/binder 模式）明确拒绝
  （c2"无上下文裸未知载荷"同族）。
- **B2 HOF 三件（建议纳入）**：list_map/list_filter/list_fold——helper 按闭包签名
  **特化 + 去重**（§7.2）；f 可为闭包字面量或具名函数当值（b 批 shim 通道，天然支持）。
  HOF 是 List 的核心用法（eval/示例语料高频），单列一档仅为控制批量大小的备选。
- **B3 List 结构相等（建议纳入）**：`==`/`!=` 对 `ls{T}` 走特化递归 eq（元素按 vt 特化，
  嵌套 `ls{ls{..}}` 递归特化）——对齐宿主 RT_LIST_EQ 行为（长短不等 false、元素跨类型
  在 L2 编译期已不可能出现——vt 相同才可比）。特化机制与 B2 同族，增量小。
- **B4 for-over-String（建议纳入，0004 既定挂账）**："ab" 迭代——char_at 物化 + UTF-8
  步进（宿主蓝本 L1418-1469）；`comp_for` 补成宿主同款三向分派（Int/String/List）。
  neg_for_string 转正。String 批 B4 推后时的原话即"随 List 批（同为迭代语义批）"。

**建议：B1+B2+B3+B4 同批。** B2/B3 的特化机制同根、B4 与 B1 的 for 改造同函数，
拆批反而要两次动 comp_for 与 vt 体系。若工期压力，降档序 B4 → B3 依次剥离。

## 5. 裁决点 2：编译期严格性包（谓词/签名/元素类型不相容）

宿主是"运行时兜底 + typechecker deferred"：list_map 的 f 签名错在 call_indirect 运行时
trap；filter 谓词非 Bool 在 RT_TRUTHY 运行时 trap；`ls{i64}` 槽混入 Float 元素在宿主
不可能发生（tagged 元素自描述）。L2 vt 精确跟踪下这些信息编译期全在手：

- **甲：编译期严格拒绝（建议）**——① filter 谓词返回 vt 必须 i32（Bool），否则
  COMPILE-ERROR；② map 的 f 签名 `(T)->R`、fold 的 f 签名 `(Acc,T)->Acc` 且与 init/首轮
  vt 一致，不符即拒（R74 调用校验同族文案）；③ `ls{i64}` 与 `ls{f64}` 之间的赋值/重赋/
  list_cons 元素注入，vt 不相容即拒。R68（let 注解）/R74（调用点）/"String 与数值比较拒"
  （0004 修订 14）既定信任边界的延续——**宿主运行期语义留给 L2.3 全语言面收官时统一
  评估是否放宽**。
- **乙：对齐宿主运行时**——放弃编译期校验，让坏程序产 trap 的 wasm。违背 R68/R74 以来
  "编译期严格校验"的既定路线（每批复审的信任基础），不建议。

**建议：甲。**

## 6. 技术设计（按建议档 B1+B2+B3+B4、裁决 2 甲展开）

### 6.1 模块布局

无新 section。helper 全部走 c1/c2 既定 extra 区机制（`extra_fns`/`extra_types` +
`cgh "hidx:<name>"` 去重，L4266 注释位）：

| helper | 签名（WASM） | 蓝本 | 备注 |
|---|---|---|---|
| rt_ls_len | (i64 xs) -> i64 | build_list_len L5181 | eqz 判 Nil（宿主 ==9 的裸值版） |
| rt_ls_get | (i64 xs, i64 i) -> i64 | build_list_get L5211 | 越界 trap（rc1 对拍一致） |
| rt_ls_range | (i64 a, i64 b) -> i64 | build_range L5159 | 左闭右开；两端 Int 编译期校验 |
| rt_split | (i64 s, i64 sep) -> i64 | RT_SPLIT 蓝本 | 返回 `ls{st}`；string 模块注册表补第 11 名 |
| rt_ls_map\<sig\> | (i64 f, i64 xs) -> i64 | build_list_map L5415 | **特化族**（B2，§6.2） |
| rt_ls_filter\<sig\> | (i64 f, i64 xs) -> i64 | build_list_filter L5454 | 特化族；谓词结果 eqz/if 消费（Bool 编译期已校验，无需 truthy） |
| rt_ls_fold\<sig\> | (i64 f, i64 acc, i64 xs) -> i64 | build_list_fold L5496 | 特化族 |
| rt_ls_eq\<T\> | (i64 a, i64 b) -> i32 | build_list_eq L5846 | 特化族（B3）；元素比较按 T 分派（i64/i32/f64/st → 既有 opcode；en/cl → 拒或后续，见 §6.3） |
| rt_char_at | (i64 s, i64 off) -> i64 | 宿主 RT_STR_CHAR_AT | B4；物化单字符 Str |

调用点内联（对齐宿主）：`list_empty()` → `i64.const 0`；`list_is_empty` → `i64.eqz` +
bool tag 还原（L2 直接 i32）；`list_head/tail` → eqz 空判 trap + `load 0/8`（元素 vt 已知，
head 读出按 vt 还原——i32 wrap / f64 reinterpret / 其余直取）。

### 6.2 HOF 特化与去重（B2）

- **特化键**：map/filter 按 `(elem_vt, f_ret_vt)`（f 形参 vt = elem_vt，由列表侧推出）；
  fold 按 `(acc_vt, elem_vt)`（f: `(acc,elem)->acc`）。键串直接用 vt 拼接
  （如 `map:i64->st`、`fold:st,i64`），Map 去重（shims 按名去重先例）。
- **helper 体内的 call_indirect**：typeidx = 闭包体签名的 type 条目（extra_types 追加），
  与调用点侧 b 批闭包调用完全同一机制——f 值在 helper 里经 table 索引调用，编译期已由
  调用点校验 sig（裁决 2 甲），运行时 typeidx 检查兜底（双保险，与 b 批一致）。
- **具名函数当值**：`list_map(double, xs)` 的 double 经 shim 成闭包值（vt "cl" 带 sig），
  调用点校验读 sig——与局部闭包同路，零新增。
- **元素写入**：map 的结果按 f_ret_vt reinterpret/extend 后 cons 入新表；filter 直通
  elem_vt；fold 的 acc 槽按 acc_vt。

### 6.3 类型流与编译路径

- `ty_vt_with_params`：`TyGeneric("List", [T])` → 递归 `ty_vt(inner)` → `"ls{" + inner + "}"`；
  `TyGeneric("Map", _)` 等其余泛型维持现拒（Map 批）。
- `infer_ex`：`ExRange(a, b)` → 两端 infer 非 i64 即拒（宿主 TYPE001 warning 的严格化，
  R68 同族）→ `Ok("ls{i64}")`；`comp_ex` 发射两端 + `call rt_ls_range`。
- import 注册：两遍式的 `module == "string"` 旁扩 `module == "list"` 分支——
  `li_builtin_entry` 表（10 内建的 helper 名/arity/prms/ret）；string 注册表补
  `split`（ret `ls{st}`，helper rt_split）。`from list import` 的 prms/ret 进摘要，
  `comp_builtin_call` 按 idx=-2 哨兵分派（String 批机制原样）。
- **元素 vt 推导**：`list_cons(h, xs)` → 两侧校验（h 的 vt 与 xs 的 T 相容；xs 是
  `ls{?}` 时结构补全为 `ls{h_vt}`——绑定层的 vt 细化，c2 "块内赋值细化"同族进
  scan_block_lets）；`list_head/get(xs)` → 返回 T；`list_tail(xs)` → 原 ls vt；
  `list_empty()` → `ls{?}`；`split(s, sep)` → `ls{st}`；range → `ls{i64}`。
- `vt_compatible` 扩：`ls{` 前缀按花括号深度取内层递归比较（en: 同款拆分函数复用）。
- **for 三向分派**（comp_for 重构）：infer iter vt →
  - `i64` → 现路径不动（产物字节目标不变）；
  - `ls{T}` → List 路径：迭代变量 `new_slot` 的 vt = T；循环 = it 槽复用 cons 指针、
    eqz 判 Nil、var = head 读出（按 T 还原）、步进 load 8；块作用域走 R79 契约
    （loop_env 拷贝，迭代变量只进拷贝）；
  - `st` → String 路径（B4）：cnt 字节偏移 + rt_char_at 物化 + 物化串头读步进；
    迭代变量 vt = st。
  - 其余 vt → 拒（"for 迭代仅支持 Int/String/List"）。
- **闭包/泛型载荷**：`ls{...}` 流经 sig 串、捕获表（8B 槽直存 i64）、c2 泛型实例
  `en:Box{ls{i64}}` 的载荷读写（8 字节 load/store）——编码无冲突，自动获得。
- **match**：Binder 模式绑定 `ls{T}` 值 → vt 进环境（c1 臂绑定机制原样）；被测 vt 与
  `ls{?}` 裸未知进 binder → 拒（c2 同族）。无 List 字面量/结构模式（宿主无，§2.2）。

## 8. 信任边界登记（本批新增，进 RFC 修订）

1. **编译期严格包（裁决 2 甲）**：HOF 签名/谓词 Bool/元素类型不相容（校验 #1/#4/#5/#6）
   ——宿主运行期 trap 或 deferred 放行，L2 编译期拒（R68/R74/0004-String 混合比较既定
   路线延续；L2.3 收官时统一评估放宽）。
2. **println(List) 与拼接提升的 List 侧**（校验 #7/#8）：宿主合法（display `"[a, b]"`
   可打可拼）；L2 拒——println(闭包)（0001）/println(Enum)（c1）同型先例，留容器显示批
   统一裁决。
3. **rt_ls_eq 元素边界**（校验 #12）：宿主 RT_EQ 递归支持枚举元素；B3 首版限
   i64/i32/f64/st/嵌套 ls 元素，en/cl 元素留后续（负例登记，不产坏 wasm）。
4. **range 两端严格 Int**（校验 #11）：宿主 TYPE001 warning 不拦截；L2 编译期拒（R68
   let 注解同族——已登记差异的第 N 次延续）。
5. **空表 head/tail、get 越界**：双侧同为运行时 trap（宿主 unreachable / 解释器错误），
   rc1 对拍一致——**非差异**，正例避界 + 边界对拍各一（两侧同 trap 同 rc 即 PASS）。
6. **for-String 迭代变量是单字符 String 物化**：宿主同（无独立 Char 类型是 v1.0 冻结
   non-goal 重申，非新增差异）。
