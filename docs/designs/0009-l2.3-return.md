# L2.3 return 语句收官批设计方案

- **文档**：docs/designs/0009-l2.3-return.md
- **性质**：动工前置设计（HANDOFF 约定：涉发射层结构变化的批次先出设计方案——先例 0001-0008）
- **基线**：`c09eb58` / v1.3.0（2026-09-27）；self_comp.lom 9361 行；verify_selfcomp 238/238 = 104 对拍 + 134 负例
- **状态**：**设计产出（动工前置，待用户裁决）**
- **上游**：RFC-0004 修订 6-24（L2.3 各批）；c2 的变体表/构造/载荷读取（match 已趟平）与 map_get 的 Some/None 构造是 `?` 的直接复用件；本批收官 L2.3 语句面（此后仅剩 L2.4 自举闭环）

---

## 1. 背景与范围

**本批目标**（对拍口径不变：双产物行为级一致——宿主 `lom build --target wasm`
vs L2 产物，stdout + rc 逐字）：L2.3 最后的语句级缺口——**return 语句与
`?` 提前返回**（RFC-0004 三处挂账"return 语句（块深度跟踪）"）。

1. **return 语句**（有值/无值两形）：函数内任意嵌套深度（if/while/for/
   match 臂/闭包体/值位 if 块内）的提前返回；
2. **`?` 表达式**（ExTry）：Ok(v)/Some(v) 解包取载荷值、Err(e)/None
   整值从所在函数提前返回——值位（`let x = f()?`）、裸语句位、块尾/
   值位 if 内；
3. 语义对齐宿主：`?` 的提前返回属于**最近函数/闭包边界**（闭包体内
   return/? 属闭包自身）；TYPE010/TYPE020 对应面在 L2 为编译期检查。

**明确不在本批**：宿主 warning 语义（L2 既定编译期严格路线）；REPL
形态（L2 非交互）；函数返回注解缺省时的类型推断（L2 现状 None→void
维持——无注解的值返回函数本就被 comp_tail 拒，负例已有）。

## 2. 现状与宿主参照系（读码结论 @ c09eb58，供料逐处实证）

### 2.1 宿主语义（蓝本）

- 解释器双通道：`?` 触发 `EarlyReturn(整个 Err/None 值)` + 显式 return
  触发 `ControlFlow::Return(v)`，`exec_block` 汇流（EarlyReturn 转
  Return 信号）穿透任意嵌套直达函数/闭包边界（interpreter.rs :703-722,
  :841-847, :1028-1053）；闭包体是独立函数边界（:1484-1490）。
- 宿主 WASM：函数体包 `block (result i64)`（$ret 块，:1250），return =
  值入栈 + `br labels.len()-1`（:1525-1535）；`?` = idx 测试（Ok=0/
  Some=2 → 读载荷 else → 原值 br $ret，:1734-1772）；**Label 栈
  Block/Loop/If 全压栈**——if 也是 label（7.2 坑）、Try 的 if 也要压
  （7.5 坑）、for 的三个运行时分派 if 也要压（W-2 坑，潜伏 7 版本的
  for-return 事故）。
- typechecker：`current_ret` 按最近函数/闭包边界 save/restore
  （mod.rs :660-663）；return 值不符 TYPE010 Warning；`?` 操作数非
  Result/Option → TYPE020 Warning；`result_compatible` **只查族不查
  载荷**（:1230-1235）。

### 2.2 L2 现状

| 位置 | 现状 |
|---|---|
| comp_one_stmt `StReturn`（:7764） | `Err("return 语句（块深度跟踪留后续批次）")` —— 唯一语句拒绝点 |
| infer_ex/comp_ex `ExTry`（:3531/:3946） | `Err("? 提前返回留 return 批（块深度跟踪）")` |
| 函数体发射（comp_one_fn :8108 / 闭包 :7063） | `ldecl + code + "0b"` —— **平铺，无 $ret 块包装**（与宿主的根本差异） |
| 控制流深度 | **全部硬编码字面量**（while/for 的 `0d01`/`0c00`、match 的 `0c01`/`0c02`）——无深度概念、无 label 栈等价物 |
| 变体设施（? 复用件，全就位） | idx 测试发射（comp_pattern_test :4295）与载荷宽度化读取（:4300-4310，f64 补 bf/i32 补 a7）——match 已趟平；map_get 的 Some(idx=2)/None(idx=3) 构造与变体表逐值对齐 |
| 负例 | neg_return_stmt（未锁文案）+ neg_c2_try_deferred（锁"? 提前返回留 return 批"） |

### 2.3 关键架构事实（供料结论，规划者确认）

- **wasm 的 `return` 指令（0x0f）从任意块深度直接返回函数、无需任何
  深度跟踪**——宿主未使用它（选了 br $ret 的历史实现），但两方案在
  wasm 验证层等价、对拍只比 stdout+rc。
- **宿主三类深度事故（7.2 if-label 漏压 / 7.5 Try if 漏压 / W-2 for
  分派 if 漏压）在 0x0f 方案下结构性不存在**——它们的根因全是深度
  计算错。
- **存量 hex 不变性**：0x0f 方案不需要 $ret 块包装 → 不含 return/? 的
  存量程序发射逐字节不变（无需按需包装设计）；br $ret 方案则需按需
  包装（含 return/? 的函数才包）才保恒等。
- `?` 的 Err/None 出口值 = 枚举指针（i64 族），函数返回 en:Result{...}/
  en:Option{...} 的签名 result 恒 i64 族（vt_hex 7e）——0x0f 的栈顶
  类型校验天然匹配。
- 闭包体编译时 cg 是共享引用——"当前函数返回 vt" 状态须在闭包体
  前后 save/restore（宿主 current_ret 先例）。

## 3. 裁决点 1：发射方案

- **乙：`return` 指令（0x0f）直发【建议】**——return：值入栈（void
  函数无值）+ `0f`；`?`：scrut 存 local → idx 测试 → Ok/Some 路读载荷
  （宽度化读取，复用 :4300 件）产出表达式值，Err/None 路 `lget scrut +
  0f`。**零深度跟踪、零 $ret 包装、存量 hex 天然不变、宿主三类深度
  事故结构性免疫**。与宿主蓝本的有意偏离（宿主 br $ret 是实现选择非
  语义要求）登记为信任边界。
- **甲：宿主同款 br $ret + 深度计数器**——cg.cgs 维护 "depth" 键、
  全部控制流发射点对称 push/pop（elif 递归链/for 四路径早退的恢复点
  全覆盖是 W-2 的 L2 版风险面）、函数体按需包 $ret 块。与宿主实现
  形态一致（可逐段平移 :1525-1772），但改动面大（30+ 发射点）、深度
  计算错误面 = 宿主已付过三次学费的坑族、存量恒等需额外按需包装
  设计。**不建议**（无对价收益——对拍不比实现形态）。

**建议：乙。**

## 4. 裁决点 2：批次范围

- **B1+B2+B3 全批【建议】**——B1 return 语句 + B2 `?` 表达式 + B3
  深嵌套组合（循环体/match 臂（Form B 块与 Form A 臂表达式内的 ?）/
  闭包体/值位 if 内/多层嵌套）**一次交付**。理由：① `?` 与 return
  语义成对（? 就是 Err/None 的提前返回），分批使 neg_c2_try_deferred
  文案空转；② 0x0f 方案下 B3 无增量机制（免深度后深嵌套只是测试面
  不是机制面）——B3 作为**验收用例面**（D5 差分 return 族 ×3 加权池
  的七模板 + 递归内 return + while×match×Form B 三层 + try_operator
  全文 + eval 020）而非独立档；③ 宿主 e2e 语义网（first_even /
  return_in_for / try_in_for / try_propagation）可直接复用为对拍蓝本。
- 分批替代（B1 先行、B2 随后小批）：仅在工期压力下有意义，0x0f 方案
  下无必要。

**建议：B1+B2+B3 全批。**

## 5. 裁决点 3：`?` 上下文校验口径

- **甲：编译期严格——族必查 + 载荷相容查【建议】**：① 操作数 vt 须
  `en:Result{...}`/`en:Option{...}`（否则编译期拒，对齐 TYPE020 面；
  非 Result/Option 的 `?` 宿主是运行时错误——L2 编译期拦，R68/R74
  既定路线）；② 所在函数（最近边界）返回 vt 须与操作数构造兼容：
  函数返回 `en:Result{A;B}` 时 `?` 的操作数须 `en:Result{...}` 族且
  **Err 载荷 vt 相容**（en:Option 同构）——宿主只查族（渐进式
  warning），L2 严格查载荷（错配的 Err 直通会产签名类型错坏 wasm，
  编译期拦是"不留坏 wasm"承诺延续）。
- **乙：对齐宿主宽松（仅查族）**——错配载荷的 `?` 产出签名类型不符
  的 wasm（如函数返回 en:Result{i64;st} 而 ? 作用于
  en:Result{i64;f64}，Err 直通 f64 族值进 i64 签名）——产不可实例化
  或静默错值模块，违背 R81 以来"编译期严格校验不留坏 WASM"边界。
  不建议。

**建议：甲。**

## 6. 技术设计（按建议档 乙 / B1+B2+B3 / 甲 展开）

### 6.1 return 语句（StReturn @ comp_one_stmt）

- 求值可选 expr → 有值时入栈（值 vt 与**当前函数返回 vt** 校验——
  不符编译期拒，文案对齐"return 值类型不符（期望 X 得 Y）——宿主
  TYPE010 warning 面，L2 编译期拒"信任边界）；void 函数 return 带值
  拒 / 非 void 函数 return 无值拒（文案同族）。
- 发射：`comp_ex(expr) + "0f"`（void：无值仅 `0f`）。
- **当前函数返回 vt 线程化**：cg.cgs 新键 "cret"（当前函数 ret vt 的
  整数编码或经 Map 直存——实施定，倾向 cg.cgs 存字符串键需查 cgs
  值域，否则经 locals 同款 Map<String,Int> 编码；最简：comp_one_fn/
  compile_closure 编译体前 set、体后 restore（闭包体前后 save/restore
  ——cg 共享引用，宿主 current_ret 先例））。
- main：void 函数同路径（`return` 无值合法）。

### 6.2 `?` 表达式（ExTry @ infer_ex/comp_ex）

- **infer**：操作数 vt 拆 `en:Result{A;B}` → 产 A；`en:Option{A}` →
  产 A（enum_vt_parts :2388 复用）；其他 vt → 编译期拒（校验 #1）。
- **comp**：`comp_ex(inner) + lset t` → idx 测试（:4295 同构件：`lget
  t + wrap + load idx + const + i32.eq`）→ if (result 按载荷 vt)：
  then 读载荷（:4300 同构件 + 宽度补码 bf/a7/无）→ else `lget t +
  0f`。if 块发射 `"04" + bt + then + "05" + else + "0b"`（bt=载荷
  vt 的 blocktype——vt_bt 复用）。
- **上下文校验**（裁决 3 甲）："cret" 与操作数 Err 载荷 vt 相容性在
  comp 时查（不符拒，文案"? 的 Err 载荷类型与所在函数返回类型不符"）。
- ex_rv（闭包尾综合）补 ExTry 臂（产载荷 vt——闭包体尾的 ? 参与
  返回类型综合）。
- 三个消费位（值位 let/裸语句/块尾与值位 if 内）经既有路径自然获得
  （供料项 5 的拦截点放开后无特化）。

### 6.3 校验总表（编译期 subset_err 拒绝无 hex）

| # | 形态 | 文案要点 | 宿主参照 |
|---|---|---|---|
| 1 | `?` 操作数非 Result/Option | "? 只能用于 Result/Option（得 vt）" | 宿主运行时错误/TYPE020 warning——L2 编译期拦（信任边界） |
| 2 | `?` 所在函数返回 vt 不相容（族或 Err 载荷） | "? 的 Err 载荷类型与所在函数返回类型不符" | 宿主仅查族 warning——L2 严格（信任边界） |
| 3 | return 值与函数返回 vt 不符 / void 带值 / 非 void 无值 | "return 值类型不符（期望 X 得 Y）" | TYPE010 warning——L2 编译期拦（信任边界） |
| 4 | 无返回注解函数（void）内 return 带值 | 同 #3 族（None 注解→void 现状维持） | — |
| 5 | `?`/return 在 void main 的带值形态 | 同 #3 | — |

### 6.5 存量不变性

0x0f 方案零包装零新键发射——**不含 return/? 的存量程序发射逐字节
不变**（全量对拍验收硬项）；函数返回 vt 线程化只在编译期状态，不进
产物。

## 7. 信任边界登记（本批新增，进 RFC 修订）

1. **return 发射用 wasm `return` 指令（0x0f）而非宿主的 br $ret**：
   语义等价（wasm 验证层两方案一致、对拍只比 stdout+rc）；宿主 br
   $ret 是历史实现选择非语义要求；0x0f 免深度跟踪使宿主三类深度
   事故（7.2/7.5/W-2）在 L2 结构性不存在。
2. **TYPE010/TYPE020 对应面编译期严格拒绝**（宿主渐进式 warning）：
   R68/R74 既定路线延续（#1-#5 校验）。
3. **`?` 载荷相容查严于宿主**（宿主仅查族）：错配 Err 直通会产签名
   类型错——编译期拦是"不留坏 wasm"承诺延续。
4. **无返回注解函数 void 现状维持**：宿主可推断，L2 编译期要求显式
   注解（既有负例域不变）。

## 11. 开放问题（动工中定，不阻塞裁决）

1. "cret" 状态载体（cg.cgs Int 值域编码 vs 并行 Map——实施取最简）；
2. `?` 的 if 块 blocktype 与两个出口的栈校验细节（Err 出口 0f 前
   lget t 的 i64 与 if (result 载荷 bt) 的 else 臂类型——else 臂发
   0f 时栈校验按 wasm 规范 return 豁免臂类型匹配，实施时以 Node
   验证器实测定形态）；
3. Form A 臂表达式中 ? 的 comp 路径（臂值经 comp_ex 自然获得，需
   对拍用例覆盖）；
4. main 内 return 的 rc 语义（void return 正常退 0；宿主对齐面）。
