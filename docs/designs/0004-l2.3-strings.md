# L2.3 String 批设计方案

- **文档**：docs/designs/0004-l2.3-strings.md
- **性质**：动工前置设计（HANDOFF 约定：涉值表示扩展的批次先出设计方案再动工——闭包批 0001 先例）
- **基线**：`3cfd3e9` / v1.2.9（2026-09-24）；self_comp.lom 5437 行；verify_selfcomp 128/128 = 52 对拍 + 76 负例
- **状态**：**已交付（2026-09-24，RFC-0004 修订 14；仓库版本 v1.2.10）**——用户裁决"按建议动工"（B1+B2+B3 / println(Bool) 顺带 / Float display 甲）；verify_selfcomp 148/148 = 62 对拍 + 86 负例，存量 52 用例 hex 逐字节不变。实施修正一处：string_to_int 因 Int|Unit 联合在 untagged 下运行时不可区分，从 B3 集合改为编译期拒绝（§4 原列 11 个内建 → 交付 10 个）
- **上游**：RFC-0004 修订 6/8/9/12（a 控制流 / b 闭包 / c1 枚举 match / c2 泛型与 Result/Option）；堆分配器与闭包值通道（b 批地基）为本批复用件

## 1. 背景与范围

L2.3 已交付 a/b/c1/c2 四批。按 RFC-0004 既定批次顺序，下一个是 **String 批**：
让 String 值流过 L2 编译器（字面量、类型流、println、比较、拼接），并按裁决
决定 string 内建子集与 for-over-String 是否随批。List/Map/json/包/return 仍留后续。

**本批目标**（对拍口径不变：双产物行为级一致——宿主 `lom build --target wasm`
vs L2 产物，stdout + rc 逐字；不做字节级一致）：

1. String 字面量表达式（`let s = "hi"`）与 String 在 let/参数/返回/赋值/if/match/
   闭包捕获/泛型载荷（`Result<Int, String>`、`Option<String>`、`en:Box{st}`）的类型流；
2. `println(String)`；
3. String/String 六种比较（Eq/NotEq/Lt/Gt/LtEq/GtEq，字节序对齐 Rust str Ord）；
4. `+` 拼接：Str/Str 直拼；非 String 侧按宿主 v0.4.1 拼接提升语义 `to_display` 后拼
   （裁决点 1 的 B2 档）；
5. match 的 String 字面量模式（字节相等，对齐宿主 rt_eq 的 STR 分支）。

**明确不在本批**（负例或后续批次）：split（返回 List，随 List 批）、
`for c in <String>`（裁决点 1 的 B4 档）、枚举/闭包值的显示（println(Enum) 仍拒）、
String 的算术（减乘除模）、`?`/return（return 批）。

## 2. 现状与宿主参照系（读码结论，行号 @ 3cfd3e9）

### 2.1 L2 现状（self_comp.lom 5437 行）

前端已就绪：`TkStr`/`ExStr`/`TyString` 解析与 `PatLit(ExStr)` 模式解析均在
（L2031/L2180，物理复用 self_interp 前端）。编译侧拒绝点六处：

| 位置 | 现状 |
|---|---|
| `ty_vt_with_params`（L2580） | `TyString` 落 `_ =>` 兜底："该参数/返回类型（String/List/Map/记录/元组留后续批次）"——**签名层 String 进不来** |
| `infer_ex`（L3047） | `ExStr` 落 `_ => Err("该表达式形态")` |
| `comp_ex`（L3421） | `ExStr` 同上兜底拒 |
| `comp_println`（L3864） | "println 只接受 Int/Float（String/Bool/Enum 留后续批次）" |
| `comp_call`（L3801） | string 模块内建全拒（只认 println/用户 fn/闭包） |

模块组装（L5290-5381）：现有 section = type/import/function/[table/memory/global]/
export/[elem]/code——**无 data(11) section**（静态字面量没有落点）；import 固定 2 个
（env.print_i64 / env.print_f64），harness（tools/selfcomp/run_selfcomp.mjs）契约同。
堆设施（bump alloc + memory + global hp=8）自 b/c1 批在位，`needs_heap` 预扫
（L4679）现扫闭包/具名函数当值/变体/枚举声明。

现存 String 相关负例 9 个（本批处置见 §6）：neg_string（println 字面量）、
neg_for_string、neg_match_string_pattern、neg_c2_result_string、
neg_closure_string_param、neg_println_bool（顺带问题，裁决点 2）、neg_enum_print
（不涉本批）、neg_nested_println（不涉本批）、neg_c2_print_generic（不涉本批）。

### 2.2 宿主参照系（src/wasm_codegen.rs）

- **值表示**：tagged `(off|ptr) << 4 | TAG_STR(4)`。**静态串在 data 段**
  `[len: u32][utf8 bytes]`（`intern_str` L992，Map 去重）；**动态串（concat 产物等）
  在堆** `[len: i32][bytes]`（rt_alloc）。两种来源**布局一致**：统一按 `ptr+0` 读
  len、`ptr+4` 起读字节——这是 L2 可以沿用裸指针表示的关键事实。
- **data 段起始**：offset 0 = `'\n'`（1 字节，rt_print 换行用，L650）；
  随后 intern "<闭包>"/"true"/"false"/"()"（L665-672）。
- **print**（build_print L2789）：Str 分支 `lom_print(ptr+4, len)` + 换行再打
  `lom_print(0, 1)`。宿主导入共 13 个（L752-769）：`lom_print` 是第 5 号
  `(i32 ptr, i32 len) -> ()`，harness 侧 `Buffer.toString('utf8')` 直出。
- **拼接提升**（build_arith L2487）：Add 任一侧 tag=STR → `display(l) + display(r)`
  后 concat；`rt_display`（L3093）对齐解释器 `to_display`（Int→itoa、F64→经宿主
  导入 `lom_ftoa`、Bool→"true"/"false"、Unit→"()"、Str→原样）。
- **比较**：`rt_lt/gt/le/ge`（L2590 区）Str/Str 走 `rt_str_cmp` 字节序（-1/0/1 与
  0 比较）；`rt_eq`（L2658）跨类型恒 false，Str/Str 走 `rt_str_eq` 逐字节。
  混合类型大小比较在宿主是 trap。
- **string 内建 helper**（RT_* 常量 L77-123）：concat/display/itoa/str_len/stoi/
  trim/upper/lower/contains/starts/ends/replace/str_cmp/str_eq/char_at(UTF-8 单字符
  物化)/char_from_code/split。全部 tagged 进出。
- **for-over-String**（For 编译 L1418 区）：`rt_str_char_at(s, byte_off)` 物化单字符
  Str，步进从物化串头读字节数。

### 2.3 关键差异：宿主 tagged vs L2 untagged 对 String 的影响

与闭包批（designs/0001 §2.4）同型：宿主 helper 全部 tagged 进出、运行时 tag 分派
兜底；L2 值通道按 vt 静态区分（"st" = i64 裸指针），helper 可以做成**裸接口**
（`st_concat(a: i64, b: i64) -> i64`，无 tag 检查）——比宿主更简，编译期 vt 校验
前置（R68/R74 既定信任边界）。宿主 helper 的指令序列主体（复制循环、逐字节比较）
可平移，仅剥掉 tag 装拆。

## 3. 值表示（既定路线，不设裁决点）

String 在 L2 的表示沿 designs/0001 裁决 A甲 的 untagged 路线自然延伸，无方向性
变更，不重开裁决：

- vt 串新增 `"st"`；`vt_hex("st") = vt_bt("st") = "7e"`（WASM 载体 i64）。
- **WASM 值 = i64 裸指针**：静态字面量 = data 段偏移（零扩展），动态串 = 堆地址。
  与 Int 的区分纯编译期（vt 跟踪），运行时无 tag——与闭包值 "cl" 同型。
- 堆对象布局对齐宿主：`[len: i32][bytes]`（len 是**字节**长度，与宿主一致）。
- 静态串 data 段布局同宿主 `[len: u32 LE][utf8 bytes]`，模块级 intern Map 去重
  （名字→偏移），data 段 offset 0 保留 1 字节 `'\n'`（println 换行 + 对齐宿主惯例）。
- c2 的 vt 体系（`tv:T` 模板 / `en:Name{arg;arg}` / sig 串）对 `"st"` 无侵入：
  分隔符与嵌套规则不变，`Result{i64;st}`、`en:Box{st}` 天然可编码。

## 4. 裁决点 1：批次范围档位

String 面横跨"值通道"与"helper 平移"两个工作量级，拆档如下：

- **B1 值通道核心（基线，必含）**：字面量/类型流（ty_vt/infer/comp/scan 预扫/
  let 注解一致性）/ println(String) / String/String 六比较 / Str/Str 拼接 /
  match String 字面量模式 / 闭包 String 参数与捕获 / 泛型载荷解禁
  （Result<Int,String> 等）。新增 helper 仅 4 个：st_eq、st_cmp、st_concat、
  st_len（len 若随 B3 则移走）。涉及负例转正 4 个（neg_string、
  neg_c2_result_string、neg_closure_string_param、neg_match_string_pattern 改锁
  "模式类型与被测值不符"）。
- **B2 拼接提升（建议纳入）**：`"n = " + 42`、`"x" + 1.5` 形态——非 String 侧
  `to_display` 后拼。需 display 家族：disp_i64（itoa）、disp_bool/disp_unit
  （静态串返回）、disp_f64（**Float display 通道是裁决点 3**）。宿主 v0.4.1 语义，
  LLM 自然写法高频形态，eval/示例语料大量存在——**建议纳入**。
- **B3 string 内建子集（建议随批或紧随批）**：纯 Str/标量进出的 11 个——
  len、int_to_string、string_to_int、starts_with、ends_with、contains、trim、
  upper、lower、replace、char_from_code（宿主 helper 蓝本全在，剥 tag 平移；
  char_from_code 需 UTF-8 编码逻辑）。**split 推后**（返回 List，随 List 批）。
  建议与 B1+B2 同批交付（helper 平移机械、单蓝本在库），若工期压力可拆为紧随的
  独立小批。
- **B4 for-over-String（建议推后）**：`for c in "ab"`——char_at 物化 + UTF-8 步进。
  独立性强、使用频率低于内建；建议随 List 批（同为迭代语义批）或独立小批。

**建议：B1+B2+B3 一次交付，B4 推后。**

## 5. 裁决点 2：println(Bool) 是否顺带解禁

现状 `neg_println_bool` 锁"println 只接受 Int/Float"。宿主 println(Bool) 支持
（lom_print_bool，打 true/false）。B2 的 display 家族反正要写 disp_bool（返回
静态串），println(Bool) 顺带打通只剩 print 通道复用（打静态 "true"/"false" 串 +
换行）。

- **顺带解禁（建议）**：负例转正；与宿主行为对齐消除一条本可避免的子集外边界
  （designs/0001 裁决 C"mut 捕获放行"同型先例——宿主 WASM 放行则 L2 不额外收紧）。
- **维持拒绝**：保守面——Bool println 与 String 批无必然耦合，留独立小批。
  代价：disp_bool 已存在却禁止其最直接的消费场景，边界显得刻意。

## 6. 裁决点 3：Float display 通道（B2 依赖项）

拼接提升中 Float 侧 to_display 的实现路线：

- **甲：平移宿主导入（建议）**——L2 模块新增导入 `env.ftoa`（宿主名 `lom_ftoa`，
  `(f64, i32 buf) -> i32`：把 to_display 格式串写入 memory、返回字节数），harness
  加一行 JS 实现（`String(v)` + fmtFloat 口径——run_selfcomp.mjs 已有 fmtFloat，
  与宿主 run_wasm.mjs 同源）。disp_f64 = 调 ftoa 到栈缓冲再 st 构造？——**更简**：
  harness 直接提供 `env.print_str` 之外加 `env.ftoa_to_str(f64) -> i64`？
  不引入非宿主形态：保持 `(f64, buf)->i32` 原签名，disp_f64 分配 32 字节堆缓冲、
  调 ftoa、按返回长度构造 Str（拷贝进新堆对象）。宿主 run_wasm.mjs 的 lom_ftoa
  实现可直接抄（JS 一行 `String(v)` + 特判）。
  - 优点：浮点显示口径与宿主**同源**（都是 JS String(v) + fmtFloat 收尾），
    "3.14"/"2.0" 形态一致有保障；零自写浮点算法、零精度风险。
  - 代价：L2 模块导入面 2→4（print_str + ftoa），harness 改两处。
- **乙：L2 自写 ftoa**——复用 l2_spike/self_interp 已验证的纯算术 to_display
  最短往返链路（spike 修订 2 的 ×2^52 缩放 + 除模取位）。零新导入，但浮点
  显示边界（±inf/NaN/整值补 .0/最短往返）要在 L2 helper 里逐点对齐宿主 JS
  口径，精度回归面大（§11.6 IEEE754 边界教训一族）。
- **丙：本批拼接提升限非 Float 操作数**——`"x" + 1.5` 编译期拒（负例登记），
  B2 降档。避免裁决但留下高频自然写法的子集外边界。

**建议：甲。** 与宿主同源是行为对拍口径下风险最小的路线。

## 7. 技术设计（按建议档 B1+B2+B3、裁决 2 顺带、裁决 3 甲展开）

### 7.1 模块布局扩展

- **data section(11)**：`has_string` 预扫（保守口径：任一 `ExStr` 字面量或 String
  字面量模式出现即真；拼接提升形态不需要静态串）→ 发 data。offset 0 = `'\n'`；
  随后 intern 字面量。**section id 升序：data(11) 排 code(10) 之后**（elem(9) 教训
  同族，动工时单测锁定排序）。无 String 的存量程序零新增 section，产物字节不变。
- **import 扩展（按需）**：`env.print_str`（`(i32 ptr, i32 len) -> ()`，println(String)
  用）恒随 data 发；B2 时加 `env.ftoa`（裁决 3 甲）。无 String 程序 import 仍 2 个。
  注意：print_str 依赖 memory 的数据段地址——data section 属 passive？**active**，
  offset 0 起全量装载（宿主同形态）；纯静态打印程序也需要 memory section 声明
  （data active 需 memory）——即 has_string → 发 data(11) + memory(5)。
- **heap_on 保守化**：任一 String 形态（含纯字面量打印）→ heap_on（发 alloc/
  memory/global）。理由：静态/动态判定易漏（模式 scrutinee 可能是 concat 结果），
  宁可多发；行为对拍不受 section 多寡影响。存量无 String 程序不变。

### 7.2 helper 家族（裸接口，编译期 vt 前置校验）

| helper | 签名（WASM） | 蓝本 | 备注 |
|---|---|---|---|
| st_eq | (i64 a, i64 b) -> i32 | build_str_eq L2971 | 剥 tag：参数已是裸指针 |
| st_cmp | (i64 a, i64 b) -> i32 | build_str_cmp L3884 | 字节序，-1/0/1 |
| st_concat | (i64 a, i64 b) -> i64 | build_str_concat L3024 | alloc 新对象；**heap 依赖** |
| st_len | (i64 a) -> i64 | build_str_len L3295 | **字符数**（数非续字节，对齐宿主 chars().count()） |
| disp_i64 | (i64 v) -> i64 | build_itoa L3197 | itoa 堆构造 |
| disp_bool / disp_unit | (…) -> i64 | 静态串返回 | data 偏移直接返回 |
| disp_f64 | (f64 v) -> i64 | 裁决 3 甲 | ftoa 导入 + 堆拷贝构造 |
| st_starts/ends/contains/trim/upper/lower/replace/stoi/char_from_code | 各按宿主 | L2080-2340 各 helper | B3；全部剥 tag 平移 |

helper 注册进 extra 区（alloc 之后的 extra_fns 机制，c1/c2 已在位）；
类型条目进 extra_types。**char_at 不做**（B4 推后）。

### 7.3 类型流与编译路径

- `ty_vt_with_params`：`TyString => Ok("st")`（L2640 兜底前加臂）；泛型参数校验
  （"暂不支持 Unit/Fn"）对 "st" 放行——`Result{i64;st}` 等解禁。
- `infer_ex`/`comp_ex`：`ExStr(s) => Ok("st")` / 发射 `i32.const <off>` +
  `i64.extend_i32_u`（off 从模块级 intern Map 取；cg 状态经 cgh 传 data hex 与
  偏移表——cg 结构加两个 Map 或并入 cgh）。
- `scan_block_lets`/`blk_val_ty`/`ex_rv` 等综合路径：随 infer_ex 自动获得。
- `comp_println`：`at == "st"` → `local.tee p; i32.wrap; i32.const 4; i32.add;
  <p wrap> i32.load 0; call print_str; i32.const 0; i32.const 1; call print_str`
  （换行字节在 data offset 0，对齐宿主形态）。Bool 分支（裁决 2 顺带）：打静态
  "true"/"false" data 串 + 换行。
- `comp_binary`：比较分支 `lt == "st" and rt == "st"` → Eq/NotEq 走 st_eq（i32 结果
  取反用 eqz），Lt/Gt/Le/Ge 走 st_cmp + 与 0 的 i32 比较；**st 与数值混合 → 编译期
  拒**（宿主 rt_eq 跨类型恒 false / rt_lt 跨类型 trap——L2 统一编译期拒，信任边界
  登记 §9）。算术分支：Add 的 `st` 参与 → 拼接路径（B2：另一侧非 st 先 disp；
  同 st 直 concat）；st 参与非 Add 算术 → 拒。
- match 模式：`PatLit(ExStr(s))` 的综合类型 = "st"（模式类型校验沿用 c1——被测
  类型非 "st" 时拒，改锁 neg_match_string_pattern）；测试发射 = comp scrutinee 后
  `i32.const <模式串 off>` + st_eq。
- 闭包/泛型：sig 串、`tv:T` 实例化、`en:Name{...}` 载荷宽度（st 是 i64 载体，
  载荷读写 8 字节 load/store）对 "st" 全部自然流动；`neg_closure_string_param`
  转正。

### 7.4 needs_heap / has_string 预扫

`scan_ex` 扩：`ExStr(_) => False`（字面量本身不触发堆，由 has_string 发 data/
memory；heap_on 由 String 形态整体保守触发，见 7.1）。`has_string(prg)` 新增
独立预扫（ExStr 或 PatLit(ExStr)）——与 needs_heap 分开登记，职责不同
（data/内存 vs alloc/global）。

## 8. 负例与对拍用例（成对交付——R74 教训）

**转正删除（4+1）**：neg_string（→ cases 53_string_basic）、neg_c2_result_string
（→ 泛型载荷对拍）、neg_closure_string_param（→ 闭包参数对拍）、
neg_println_bool（裁决 2 顺带 → println(Bool) 对拍）；neg_match_string_pattern
**保留改锁**：原形态（Int scrutinee + "x" 模式）从"String 模式留后续"改为
"模式类型与被测值不符（期望 i64 得 st）"，EXPECTED_NEGATIVE_MESSAGES 同步。

**新增负例（锁具体拒绝原因 + 无 hex，预计 10-14 个）**：

| 负例 | 锁定 |
|---|---|
| neg_str_num_compare | String 与数值比较编译期拒 |
| neg_str_arith | String 参与减/乘/除/模 |
| neg_str_index | String 下标访问（List 批前不支持） |
| neg_str_neg | String 一元负 |
| neg_str_call | 对 String 值调用 |
| neg_string_builtin_arity / _type | string 内建 arity/类型校验（B3） |
| neg_stoi_fail 形态 | string_to_int 失败返回 Unit 的消费形态（对齐宿主裸值协议——失败 Unit 进 println 拒） |
| neg_char_from_code_range | 无效码点（宿主 trap → L2 helper 同 trap，正例避界 + 编译期不拦的如实登记） |
| neg_match_str_pattern_mixed | 被测 String 配 Int 字面量模式（反向类型不符） |
| neg_str_annot_mismatch | `let s: Int = "x"`（R68 注解一致性延伸） |

**新增对拍用例（预计 8-12 个）**：字面量/println、拼接提升（Int/Float/Bool/Unit
侧）、六比较（含字节序边界 "ab" < "b"）、len（多字节字符——"你好" len=2）、
string 内建矩阵（B3 全 11 个）、match String 模式、闭包 String 捕获/参数、
Result<Int,String> 载荷流、泛型 `en:Box{st}`、静态/动态串混用（字面量 concat 后
再 concat）。

## 9. 信任边界登记（本批新增，进 RFC 修订）

1. **String/数值混合比较**：宿主 rt_eq 跨类型恒 false（返回 Bool）、rt_lt 族跨类型
   trap；L2 统一编译期拒绝（R68/R74 既定"编译期严格校验"路线延续）。
2. **拼接提升的 Float 显示**：裁决 3 甲下宿主与 L2 同源（JS String(v)），
   fmtFloat 收尾口径一致；乙路线下将存在双实现精度风险（不建议）。
3. **trim/upper/lower 的 ASCII 语义**：宿主 WASM helper 即 ASCII（与解释器 Unicode
   空白的差异是宿主既有已登记差异），L2 平移继承——对拍双方同为 WASM 产物，
   不扩大差异。
4. **string_to_int 失败返回 Unit**：宿主裸值协议（成功 Int 失败 Unit，非 Option）；
   L2 同口径——失败 Unit 流入 println/算术按既有 void 检查拒绝。
5. **println(Bool) 顺带解禁**（裁决 2）：从"子集外负例"变"对齐宿主"，负例转正。
